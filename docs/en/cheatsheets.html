W1What is the Internet and what is a protocol?

Definitions (learn by heart)#

  • Host / end system — device at the network edge, runs applications.
  • Packet switch — router or switch, forwards packets.
  • Link — fiber, copper, radio, satellite; has a bandwidth in bit/s.
  • Network — devices + routers + links managed by one organization.
  • Internet — network of networks, interconnected ISPs.
  • Protocol — format + order + actions for messages.
  • RFC — standard document; IETF — who writes them.

Two views of the Internet#

  1. "Nuts and bolts": hosts, routers/switches, links, networks.
  2. "Service": infrastructure for applications + programming interface (in Java: sockets Socket, DatagramSocket).

How to describe a protocol step by step (project, test)#

  1. List the participants (client, server, proxy).
  2. For every message give the exact format (words, spaces, \r\n).
  3. Describe the order: who starts, what answers what.
  4. Describe actions and errors: unknown command, no answer.
  5. Add an example conversation (like in an RFC).

  • Twisted pair Cat 5: 100 Mb/s–1 Gb/s; Cat 6: 10 Gb/s.
  • Coax: many channels, hundreds of Mb/s per channel.
  • Fiber: 10–100+ Gb/s, immune to noise.

Transmission delay — step by step#

  1. LLL in bytes → ×8\times 8×8 → bits.
  2. RRR in Mb/s → ×106\times 10^6×106 → bit/s.
  3. dtrans=L/Rd_{trans} = L / Rdtrans​=L/R [s].
  4. Result ×1000 → ms.

Example: 1500 B at 100 Mb/s → 12 000 / 10⁸ = 0.12 ms.

W3Network core — packet switching and circuit switching

Formulas#

  • One link: dtrans=L/Rd_{trans} = L/Rdtrans​=L/R.
  • Store-and-forward, 1 packet, NNN links: N⋅L/RN \cdot L/RN⋅L/R.
  • PPP packets, NNN links: (N+P−1)⋅L/R(N + P - 1)\cdot L/R(N+P−1)⋅L/R.
  • TDM: circuit rate =R/number of slots= R / \text{number of slots}=R/number of slots.
  • Circuits: number of users =⌊C/r⌋= \lfloor C / r \rfloor=⌊C/r⌋.
  • Packets: P(X>k)=1−∑i=0k(Ni)pi(1−p)N−iP(X > k) = 1 - \sum_{i=0}^{k}\binom{N}{i}p^i(1-p)^{N-i}P(X>k)=1−∑i=0k​(iN​)pi(1−p)N−i.

Facts#

  • Router: the whole packet must arrive before it goes on.
  • Arrivals > output rate → queue; full buffer → loss.
  • Forwarding = local (table), routing = global (algorithms).
  • Circuits: reservation, guarantee, waste; FDM (bands), TDM (slots).
  • Lecture example: 1 Gb/s, 100 Mb/s, 10% → circuits 10 users, packets 35 users with P ≈ 0.0004.

"File over a TDM circuit" step by step#

  1. Circuit rate = R / number of slots.
  2. Time = file size [bit] / circuit rate.
  3. Add the circuit setup time.

W4Internet structure — "a network of networks"

Hierarchy (bottom-up)#

  1. Access ISP — home, company, university access.
  2. Regional ISP — collects traffic from local access ISPs.
  3. Tier-1 ISP — global (Level 3, Sprint, AT&T, NTT).
  4. Content provider networks — Google, Microsoft, Akamai, Facebook: own networks, bypass tier-1.

Keywords#

  • Customer–provider: economic agreement, the customer pays for transit.
  • IXP: exchange point of many networks.
  • Peering: direct connection of two networks.
  • POP: point of presence of a provider network.
  • The structure comes from economics and policy, not from one master plan.

Counting "everyone-to-everyone" links#

  • N(N−1)/2N(N-1)/2N(N−1)/2, e.g. 1000 networks → 499,500 links → O(N2)O(N^2)O(N2), doesn't scale.

W5Network performance — delay, loss and throughput

Formulas#

  • dnodal=dproc+dqueue+dtrans+dpropd_{nodal} = d_{proc} + d_{queue} + d_{trans} + d_{prop}dnodal​=dproc​+dqueue​+dtrans​+dprop​
  • dtrans=L/Rd_{trans} = L / Rdtrans​=L/R (L in bits!)
  • dprop=d/sd_{prop} = d / sdprop​=d/s, s≈2⋅108s \approx 2 \cdot 10^8s≈2⋅108 m/s
  • Traffic intensity: I=La/RI = La / RI=La/R (≈0 small, →1 large, >1 infinite)
  • Throughput =min⁡(Rs,Rc,R/n)= \min(R_s, R_c, R/n)=min(Rs​,Rc​,R/n); download time =F/throughput= F / \text{throughput}=F/throughput
  • Path of NNN links: N⋅dnodalN \cdot d_{nodal}N⋅dnodal​ (textbook)

"Compute the delay" step by step#

  1. Write down the data and convert units: B → bit (×8), Mb/s → bit/s (×10⁶), km → m (×1000).
  2. dtrans=L/Rd_{trans} = L/Rdtrans​=L/R.
  3. dprop=d/sd_{prop} = d/sdprop​=d/s.
  4. Add dprocd_{proc}dproc​ and dqueued_{queue}dqueue​ (if given; usually 0).
  5. Multiply by the number of links (store-and-forward).
  6. Result in ms (×1000).

Caravan#

  • 10 cars × 12 s = 120 s + 100 km / 100 km/h = 60 min → 62 min.
  • 1000 km/h, 1 min/car → first car at booth 2 after 7 min, 3 cars still waiting.

traceroute#

  • TTL = i → router i answers; 3 measurements per router; * * * = no answer.
  • Windows: tracert, Linux/macOS: traceroute.

Facts from the lecture#

  • The Internet was designed for "mutually trusting users" → security added later, in all layers.
  • DDoS: 1) select target, 2) break into hosts (botnet), 3) send packets to target.
  • Wireshark = free packet sniffer.

Practice (author's notes)#

  • Base64 ≠ encryption → passwords only over HTTPS.
  • Timeouts and threads protect your server from being "frozen" by one client.
  • Sniff only your own traffic.

  • Switch: layers 1–2. Router: layers 1–3. Host: 1–5.

OSI = 7 layers#

  • Internet + presentation (encryption, compression) + session (synchronization, checkpoints).

Header overhead step by step#

  1. Add up the headers (e.g. TCP 20 + IP 20 + Ethernet 18 = 58 B).
  2. Frame = data + headers.
  3. Efficiency = data / frame.

W8Internet history — from ARPAnet to smartphones

Timeline (exam minimum)#

  • 1961 Kleinrock — queueing theory, packets are effective.
  • 1964 Baran — packets in military nets.
  • 1967 ARPA conceives ARPAnet; 1969 first node.
  • 1970 ALOHAnet (Hawaii, satellite).
  • 1972 ARPAnet demo, NCP, first e-mail, 15 nodes.
  • 1974 Cerf and Kahn — internetworking.
  • 1976 Ethernet (Xerox PARC).
  • 1979 ARPAnet: 200 nodes.
  • 1982 SMTP; 1983 TCP/IP + DNS; 1985 FTP; 1988 TCP congestion control.
  • 1991 commercial use of NSFnet; 1995 NSFnet decommissioned.
  • ~1990 Web: HTML, HTTP (Berners-Lee); 1994 Mosaic → Netscape.
  • 2007 iPhone; 2017 ~18 billion devices.

Cerf and Kahn's principles#

  1. Minimalism, autonomy (no internal changes).
  2. Best effort.
  3. Stateless routing.
  4. Decentralized control.

C1Your first distributed program — a relay of processes in a ring

Concepts#

  • Port = a process's "door" (0–65535). Socket = IP + port.
  • localhost = 127.0.0.1 = this computer.
  • Server: new ServerSocket(port) → accept() (waits).
  • Client: new Socket(host, port) → connects.
  • The client's port is random (ephemeral).

Start order#

  1. First the processes that listen.
  2. Then the one that starts sending.
  3. Or: retry the connection every few hundred ms.

Configuration#

  • Properties p = new Properties(); p.load(new FileInputStream(file));
  • p.getProperty("listenPort") → Integer.parseInt(...).
  • Never hard-code IPs and ports.

Errors#

  • Connection refused → nobody listens.
  • Address already in use → port taken.
  • "Hangs" → waiting in accept()/readLine(); check flush().
  • Who uses a port: netstat -ano | findstr PORT / ss -ltnp / lsof -i :PORT.

C3TCP sockets in Java — your own mini HTTP server and client

TCP server — skeleton#

  1. ServerSocket ss = new ServerSocket(port);
  2. Socket s = ss.accept(); (waits)
  3. BufferedReader in = new BufferedReader(new InputStreamReader(s.getInputStream(), UTF_8));
  4. PrintWriter out = new PrintWriter(new OutputStreamWriter(s.getOutputStream(), UTF_8));
  5. read → process → out.print(...); out.flush();
  6. s.close(); (and go back to accept())

TCP client — skeleton#

  1. Socket s = new Socket(host, port);
  2. send lines + flush()
  3. read while ((line = in.readLine()) != null) (if the server closes) or until an end marker
  4. s.close();

HTTP/1.1 request — template#

Server decision#

"Hangs"? Check#

flush() · line ending \r\n · empty line after headers · Connection: close.

C4Talking to a text server — a line-by-line client

Before writing a client#

  1. Who speaks first? (check with nc -C host port)
  2. Line format and line ending (\r\n).
  3. How to recognise the end of an answer?
  4. What does an error look like?

5 ways to detect the end of an answer#

  • known number of lines → for
  • count in a header (BEGIN n) → read n
  • marker (END) → while (!line.equals("END"))
  • server closes → while ((line = in.readLine()) != null)
  • silence → setSoTimeout + SocketTimeoutException

Helper methods (pattern)#

  • send(line): out.print(line + "\r\n"); out.flush(); + log
  • read(): readLine(), null → "server closed" exception; log
  • expect(prefix): read() + check the beginning

Saving to a file#

  • BufferedWriter w = new BufferedWriter(new FileWriter("out.txt"));
  • without the first and last line: list.subList(1, list.size() - 1)

Don't#

  • Use in.available() as "end of message".
  • Read the answer before reading the greeting.
  • Forget flush().

C5TCP and UDP together — a stream vs datagrams

UDP — recipe#

  • Server: DatagramSocket s = new DatagramSocket(port);
  • Client: DatagramSocket s = new DatagramSocket(); s.setSoTimeout(1000);
  • Send: byte[] b = text.getBytes(UTF_8); s.send(new DatagramPacket(b, b.length, InetAddress.getByName(host), port));
  • Receive: DatagramPacket p = new DatagramPacket(new byte[1500], 1500); s.receive(p);
  • Text: new String(p.getData(), 0, p.getLength(), UTF_8)
  • Reply: new DatagramPacket(b, b.length, p.getAddress(), p.getPort())

TCP vs UDP#

TCPUDP
connectionyesno
guaranteesyesno
message boundariesno (stream)yes (datagram)
lossretransmissiontimeout in your code

Traps#

  • always getLength();
  • a new packet for every receive (or setLength);
  • too small buffer = truncated message, no error;
  • TCP port and UDP port with the same number are two different ports.

RTT#

long t = System.nanoTime(); send...; receive...; (System.nanoTime() - t) / 1e6 = ms.

C6DNS from the inside — a query built by hand, byte by byte

Header (12 B)#

ID(2) · FLAGS(2) · QDCOUNT(2) · ANCOUNT(2) · NSCOUNT(2) · ARCOUNT(2) — big-endian.

Flags#

QR(15) · OPCODE(14–11) · AA(10) · TC(9) · RD(8) · RA(7) · Z(6–4) · RCODE(3–0).

  • query: 0x0100 (RD=1); typical answer: 0x8180; NXDOMAIN: RCODE = 3.

Building a query step by step#

  1. writeShort(id), writeShort(0x0100), writeShort(1), 3× writeShort(0).
  2. For every label: writeByte(len) + the letters' bytes; at the end writeByte(0).
  3. writeShort(QTYPE) (A=1, NS=2, CNAME=5, MX=15, AAAA=28), writeShort(1) (IN).
  4. Send over UDP to port 53, 512 B answer buffer, timeout.

Parsing an answer step by step#

  1. Check the ID, then the flags and RCODE.
  2. Read the counters.
  3. Skip the question: name + 4 bytes.
  4. For each record: NAME (watch for C0 xx), TYPE, CLASS, TTL (4 B), RDLENGTH, RDATA.
  5. A → 4 bytes & 0xFF joined with dots.

Traps#

  • signed byte → & 0xFF.
  • Pointer: b >= 0xC0, offset = ((b1 & 0x3F) << 8) | b2; the name ends after a pointer.

nslookup / Wireshark#

  • nslookup name, -type=NS, -type=MX, nslookup IP (reverse).
  • "Non-authoritative" = from a cache.
  • Filter dns, udp.port == 53; flush: ipconfig /flushdns.

C7TCP under the microscope — sequence numbers, RTT, window and slow start in Wireshark

Handshake#

SYN (seq = x) → SYN+ACK (seq = y, ack = x+1) → ACK (ack = y+1).

seq / ack#

  • next seq = seq + data length;
  • ack = next expected byte; ACK is cumulative;
  • SYN and FIN each use 1 number;
  • Wireshark: relative numbers (raw in a separate field).

Formulas#

  • Est=0.875⋅Est+0.125⋅Sample\text{Est} = 0.875\cdot\text{Est} + 0.125\cdot\text{Sample}Est=0.875⋅Est+0.125⋅Sample (start: Est = 1st sample)
  • Dev=0.75⋅Dev+0.25⋅∣Sample−Est∣\text{Dev} = 0.75\cdot\text{Dev} + 0.25\cdot|\text{Sample} - \text{Est}|Dev=0.75⋅Dev+0.25⋅∣Sample−Est∣; Timeout=Est+4⋅Dev\text{Timeout} = \text{Est} + 4\cdot\text{Dev}Timeout=Est+4⋅Dev
  • window = Window Size Value × multiplier
  • throughput = bytes / time (×8 → bit/s)

Wireshark#

  • filter tcp, tcp.flags.syn == 1, tcp.analysis.retransmission, tcp.stream eq 0;
  • Statistics → TCP Stream Graphs → Round Trip Time / Time-Sequence (Stevens);
  • raw seq: Preferences → Protocols → TCP → untick Relative sequence numbers.

Slow start vs congestion avoidance#

  • ×2 per RTT → slow start; +1 MSS per RTT → congestion avoidance;
  • gap between fleets ≈ RTT.

The practical test — training with the DrillServer

Client template (core)#

  • Socket s = new Socket(host, port);
  • in = new BufferedReader(new InputStreamReader(s.getInputStream(), UTF_8));
  • out = new PrintWriter(new OutputStreamWriter(s.getOutputStream(), UTF_8));
  • send(x): out.print(x + "\r\n"); out.flush(); + log
  • read(): readLine(); null → exception; log

Task patterns#

  • 1 line, many numbers → split("\\s+") + Long.parseLong.
  • N lines → for (i < N) list.add(read()).
  • big numbers → new BigInteger(s), .add, .max, .compareTo.
  • several answer lines → a separate send for each.
  • stream → read 1, answer 1, flush.
  • unknown length → setSoTimeout(500) + catch (SocketTimeoutException) → reset setSoTimeout(0).

Order during the test#

  1. Save the description to a file. 2. Check the deadline. 3. Task by task, with a repetition loop. 4. Read the verdict after every answer.

Training#

The project — a proxy network connecting TCP and UDP servers

Base commands#

GET NAMES → OK n k1 … kn · GET VALUE k → OK v/NA · SET k v → OK/NA · QUIT → (nothing) · other → NA.

Running#

java Proxy -port P -server host port [-server host port ...] — a bad parameter → error + exit.

Points#

150 (1 protocol, no proxies) · 300 (2 protocols, no proxies) · 300 (1 protocol, tree) · 400 (2 protocols, tree) · 500 (2 protocols, cycles). You declare → everything must work, or 0.

Architecture#

  1. parameters → 2. TCP+UDP listeners (threads) → 3. one command handler → 4. detection + key table → 5. forwarding with timeouts → 6. proxy–proxy protocol → 7. ID + seen + TTL (cycles) → 8. QUIT to everyone.

Traps#

  • UDP to UDPServer: trailing space after the command.
  • answers: one line; UDP ≤ 256 B.
  • QUIT: don't wait for an answer.
  • validate commands (incomplete ones kill the server).
  • GET NAMES: unique names + correct counter.
  • timeouts everywhere; ConcurrentHashMap.

Submission#

javac *.java without packages · only your .java + scripts + "Dokumentacja (index number).pdf" · localhost · no hard-coded IPs/ports · GAKKO before the deadline.
