W1Czym jest Internet i czym jest protokół?

Definicje (na pamięć)#

  • Host / system końcowy — urządzenie na brzegu sieci, uruchamia aplikacje.
  • Przełącznik pakietów — router lub switch, przekazuje pakiety dalej.
  • Łącze — światłowód, miedź, radio, satelita; ma przepustowość w bit/s.
  • Sieć — urządzenia + routery + łącza zarządzane przez jedną organizację.
  • Internet — sieć sieci, połączeni dostawcy ISP.
  • Protokół — format + kolejność + akcje dla komunikatów.
  • RFC — dokument ze standardem; IETF — kto je pisze.

Dwa spojrzenia na Internet#

  1. „Śrubki i nakrętki”: hosty, routery/switche, łącza, sieci.
  2. „Usługa”: infrastruktura dla aplikacji + interfejs programistyczny (w Javie: gniazda Socket, DatagramSocket).

Jak opisać protokół krok po kroku (projekt, kolokwium)#

  1. Wypisz uczestników (klient, serwer, proxy).
  2. Dla każdego komunikatu podaj dokładny format (słowa, spacje, \r\n).
  3. Opisz kolejność: kto zaczyna, co jest odpowiedzią na co.
  4. Opisz akcje i błędy: co zrobić z nieznaną komendą, brakiem odpowiedzi.
  5. Dodaj przykładową rozmowę (jak w RFC).

Media#

  • Koncentryk: wiele kanałów, setki Mb/s na kanał.
  • Światłowód: 10–100+ Gb/s, odporny na zakłócenia.

Opóźnienie transmisji — krok po kroku#

  1. LLL w bajtach → ×8\times 8×8 → bity.
  2. RRR w Mb/s → ×106\times 10^6×106 → bit/s.
  3. dtrans=L/Rd_{trans} = L / Rdtrans​=L/R [s].
  4. Wynik ×1000 → ms.

Przykład: 1500 B przy 100 Mb/s → 12 000 / 10⁸ = 0,12 ms.

W3Rdzeń sieci — przełączanie pakietów i przełączanie obwodów

Wzory#

  • Jedno łącze: dtrans=L/Rd_{trans} = L/Rdtrans​=L/R.
  • Store-and-forward, 1 pakiet, NNN łączy: N⋅L/RN \cdot L/RN⋅L/R.
  • PPP pakietów, NNN łączy: (N+P−1)⋅L/R(N + P - 1)\cdot L/R(N+P−1)⋅L/R.
  • TDM: szybkość obwodu =R/liczba szczelin= R / \text{liczba szczelin}=R/liczba szczelin.
  • Obwody: liczba użytkowników =⌊C/r⌋= \lfloor C / r \rfloor=⌊C/r⌋.
  • Pakiety: P(X>k)=1−∑i=0k(Ni)pi(1−p)N−iP(X > k) = 1 - \sum_{i=0}^{k}\binom{N}{i}p^i(1-p)^{N-i}P(X>k)=1−∑i=0k​(iN​)pi(1−p)N−i.

Fakty#

  • Router: cały pakiet musi dojść, zanim pójdzie dalej.
  • Napływ > wyjście → kolejka; pełny bufor → utrata.
  • Forwarding = lokalnie (tablica), routing = globalnie (algorytmy).
  • Obwody: rezerwacja, gwarancja, marnowanie; FDM (pasma), TDM (szczeliny).
  • Przykład z wykładu: 1 Gb/s, 100 Mb/s, 10% → obwody 10 osób, pakiety 35 osób przy P ≈ 0,0004.

Zadanie „plik przez obwód TDM” krok po kroku#

  1. Szybkość obwodu = R / liczba szczelin.
  2. Czas = rozmiar pliku [bit] / szybkość obwodu.
  3. Dodaj czas zestawienia połączenia.

W4Struktura Internetu — „sieć sieci”

Hierarchia (od dołu)#

  1. Access ISP — dostawca dostępu (dom, firma, uczelnia).
  2. Regional ISP — zbiera ruch od lokalnych dostawców.
  3. Tier-1 ISP — globalni (Level 3, Sprint, AT&T, NTT).
  4. Content provider networks — Google, Microsoft, Akamai, Facebook: własne sieci, omijają tier-1.

Słowa-klucze#

  • Klient–dostawca: umowa ekonomiczna, klient płaci za tranzyt.
  • IXP: punkt wymiany ruchu wielu sieci.
  • Peering: bezpośrednie połączenie dwóch sieci.
  • POP: punkt obecności sieci dostawcy.
  • Struktura wynika z ekonomii i polityki, nie z jednego planu.

Liczenie połączeń „każdy z każdym”#

  • N(N−1)/2N(N-1)/2N(N−1)/2, np. 1000 sieci → 499 500 łączy → O(N2)O(N^2)O(N2), nie skaluje się.

Zadanie „policz opóźnienie” krok po kroku#

  1. Wypisz dane i zamień jednostki: B → bit (×8), Mb/s → bit/s (×10⁶), km → m (×1000).

Fakty z wykładu#

  • Internet projektowano dla „ufających sobie użytkowników” → bezpieczeństwo dodawane później, we wszystkich warstwach.
  • DDoS: 1) wybierz cel, 2) przejmij hosty (botnet), 3) wysyłaj pakiety do celu.

Praktyka (od autora)#

  • Base64 ≠ szyfrowanie → hasła tylko przez HTTPS.
  • Timeouty i wątki chronią Twój serwer przed „zawieszeniem” przez jednego klienta.
  • Sniffuj tylko własny ruch.

W8Historia Internetu — od ARPAnetu do smartfonów

Oś czasu (minimum na egzamin)#

  • 1961 Kleinrock — teoria kolejek, pakiety są efektywne.
  • 1964 Baran — pakiety w sieciach wojskowych.
  • 1967 ARPA projektuje ARPAnet; 1969 pierwszy węzeł.
  • 1970 ALOHAnet (Hawaje, satelita).
  • 1972 demo ARPAnetu, NCP, pierwszy e-mail, 15 węzłów.
  • 1974 Cerf i Kahn — internetworking.
  • 1976 Ethernet (Xerox PARC).
  • 1979 ARPAnet: 200 węzłów.
  • 1982 SMTP; 1983 TCP/IP + DNS; 1985 FTP; 1988 kontrola przeciążenia TCP.
  • 1991 komercyjne użycie NSFnet; 1995 NSFnet wyłączony.
  • ~1990 WWW: HTML, HTTP (Berners-Lee); 1994 Mosaic → Netscape.
  • 2007 iPhone; 2017 ~18 mld urządzeń.

Zasady Cerfa i Kahna#

  1. Minimalizm, autonomia (bez zmian wewnątrz sieci).
  2. Best effort.
  3. Routing bezstanowy.
  4. Zdecentralizowane sterowanie.

C1Pierwszy program rozproszony — sztafeta procesów w pierścieniu

Pojęcia#

  • Port = „drzwi” procesu (0–65535). Gniazdo = IP + port.
  • localhost = 127.0.0.1 = ten sam komputer.
  • Serwer: new ServerSocket(port) → accept() (czeka).
  • Klient: new Socket(host, port) → łączy się.
  • Port klienta jest losowy (efemeryczny).

Kolejność uruchamiania#

  1. Najpierw procesy, które nasłuchują.
  2. Potem ten, który zaczyna wysyłać.
  3. Albo: ponawiaj połączenie co kilkaset ms.

Konfiguracja#

  • Properties p = new Properties(); p.load(new FileInputStream(plik));
  • p.getProperty("listenPort") → Integer.parseInt(...).
  • Nigdy nie hardkoduj IP i portów.

Błędy#

  • Connection refused → nikt nie nasłuchuje.
  • Address already in use → port zajęty.
  • „Wisi” → czeka na accept()/readLine(); sprawdź flush().
  • Kto zajmuje port: netstat -ano | findstr PORT / ss -ltnp / lsof -i :PORT.

C3Gniazda TCP w Javie — własny mini-serwer HTTP i klient

Serwer TCP — szkielet#

  1. ServerSocket ss = new ServerSocket(port);
  2. Socket s = ss.accept(); (czeka)
  3. BufferedReader in = new BufferedReader(new InputStreamReader(s.getInputStream(), UTF_8));
  4. PrintWriter out = new PrintWriter(new OutputStreamWriter(s.getOutputStream(), UTF_8));
  5. czytaj → przetwórz → out.print(...); out.flush();
  6. s.close(); (i wróć do accept())

Klient TCP — szkielet#

  1. Socket s = new Socket(host, port);
  2. wyślij linie + flush()
  3. czytaj while ((line = in.readLine()) != null) (jeśli serwer zamyka) albo do znacznika końca
  4. s.close();

C4Rozmowa z serwerem tekstowym — klient linia po linii

Przed pisaniem klienta#

  1. Kto mówi pierwszy? (sprawdź nc -C host port)
  2. Format linii i koniec linii (\r\n).
  3. Jak poznać koniec odpowiedzi?
  4. Jak wygląda błąd?

5 sposobów na koniec odpowiedzi#

  • znana liczba linii → for
  • liczba w nagłówku (BEGIN n) → przeczytaj n
  • znacznik (END) → while (!line.equals("END"))
  • serwer zamyka → while ((line = in.readLine()) != null)
  • cisza → setSoTimeout + SocketTimeoutException

Pomocnicze metody (wzór)#

  • send(line): out.print(line + "\r\n"); out.flush(); + log
  • read(): readLine(), null → wyjątek „serwer zamknął”; log
  • expect(prefix): read() + sprawdzenie początku

Zapis do pliku#

  • BufferedWriter w = new BufferedWriter(new FileWriter("out.txt"));
  • bez pierwszej i ostatniej linii: list.subList(1, list.size() - 1)

Nie rób#

  • in.available() jako „koniec wiadomości”.
  • Czytania odpowiedzi przed odczytaniem powitania.
  • Zapominania o flush().

C5TCP i UDP razem — strumień kontra datagramy

UDP — przepis#

  • Serwer: DatagramSocket s = new DatagramSocket(port);
  • Klient: DatagramSocket s = new DatagramSocket(); s.setSoTimeout(1000);
  • Wyślij: byte[] b = text.getBytes(UTF_8); s.send(new DatagramPacket(b, b.length, InetAddress.getByName(host), port));
  • Odbierz: DatagramPacket p = new DatagramPacket(new byte[1500], 1500); s.receive(p);
  • Tekst: new String(p.getData(), 0, p.getLength(), UTF_8)
  • Odpowiedz: new DatagramPacket(b, b.length, p.getAddress(), p.getPort())

Pułapki#

  • zawsze getLength();
  • nowy pakiet do każdego receive (albo setLength);
  • za mały bufor = ucięta wiadomość bez błędu;
  • port TCP i UDP o tym samym numerze to dwa różne porty.

RTT#

long t = System.nanoTime(); send...; receive...; (System.nanoTime() - t) / 1e6 = ms.

C6DNS od środka — zapytanie zbudowane ręcznie, bajt po bajcie

Nagłówek (12 B)#

ID(2) · FLAGS(2) · QDCOUNT(2) · ANCOUNT(2) · NSCOUNT(2) · ARCOUNT(2) — big-endian.

Flagi#

QR(15) · OPCODE(14–11) · AA(10) · TC(9) · RD(8) · RA(7) · Z(6–4) · RCODE(3–0).

  • zapytanie: 0x0100 (RD=1); typowa odpowiedź: 0x8180; NXDOMAIN: RCODE = 3.

Budowa zapytania krok po kroku#

  1. writeShort(id), writeShort(0x0100), writeShort(1), 3× writeShort(0).
  2. Dla każdej etykiety: writeByte(dł.) + bajty liter; na końcu writeByte(0).
  3. writeShort(QTYPE) (A=1, NS=2, CNAME=5, MX=15, AAAA=28), writeShort(1) (IN).
  4. Wyślij UDP na port 53, bufor odpowiedzi 512 B, timeout.

Rozbiór odpowiedzi krok po kroku#

  1. Sprawdź ID, potem flagi i RCODE.
  2. Przeczytaj liczniki.
  3. Przeskocz pytanie: nazwa + 4 bajty.
  4. Dla każdego rekordu: NAME (uwaga na C0 xx), TYPE, CLASS, TTL (4 B), RDLENGTH, RDATA.
  5. A → 4 bajty & 0xFF z kropkami.

Pułapki#

  • byte ze znakiem → & 0xFF.
  • Wskaźnik: b >= 0xC0, offset = ((b1 & 0x3F) << 8) | b2; po wskaźniku nazwa się kończy.

nslookup / Wireshark#

  • nslookup nazwa, -type=NS, -type=MX, nslookup IP (odwrotne).
  • „Non-authoritative” = z cache.
  • Filtr dns, udp.port == 53; flush: ipconfig /flushdns.

C7TCP pod lupą — numery sekwencyjne, RTT, okno i slow start w Wiresharku

Nawiązanie połączenia#

SYN (seq = x) → SYN+ACK (seq = y, ack = x+1) → ACK (ack = y+1).

seq / ack#

  • następny seq = seq + długość danych;
  • ack = następny oczekiwany bajt; ACK skumulowany;
  • SYN i FIN zużywają po 1 numerze;
  • Wireshark: numery względne (raw w osobnym polu).

Wzory#

  • Est=0,875⋅Est+0,125⋅Sample\text{Est} = 0{,}875\cdot\text{Est} + 0{,}125\cdot\text{Sample}Est=0,875⋅Est+0,125⋅Sample (start: Est = 1. próbka)
  • Dev=0,75⋅Dev+0,25⋅∣Sample−Est∣\text{Dev} = 0{,}75\cdot\text{Dev} + 0{,}25\cdot|\text{Sample} - \text{Est}|Dev=0,75⋅Dev+0,25⋅∣Sample−Est∣; Timeout=Est+4⋅Dev\text{Timeout} = \text{Est} + 4\cdot\text{Dev}Timeout=Est+4⋅Dev
  • okno = Window Size Value × mnożnik
  • przepustowość = bajty / czas (×8 → bit/s)

Wireshark#

  • filtr tcp, tcp.flags.syn == 1, tcp.analysis.retransmission, tcp.stream eq 0;
  • Statistics → TCP Stream Graphs → Round Trip Time / Time-Sequence (Stevens);
  • surowe seq: Preferences → Protocols → TCP → odznacz Relative sequence numbers.

Slow start vs unikanie przeciążenia#

  • ×2 co RTT → slow start; +1 MSS co RTT → congestion avoidance;
  • odstęp między flotyllami ≈ RTT.

Kolokwium praktyczne — trening z serwerem DrillServer

Szablon klienta (rdzeń)#

  • Socket s = new Socket(host, port);
  • in = new BufferedReader(new InputStreamReader(s.getInputStream(), UTF_8));
  • out = new PrintWriter(new OutputStreamWriter(s.getOutputStream(), UTF_8));
  • send(x): out.print(x + "\r\n"); out.flush(); + log
  • read(): readLine(); null → wyjątek; log

Wzorce zadań#

  • 1 linia, wiele liczb → split("\\s+") + Long.parseLong.
  • N linii → for (i < N) list.add(read()).
  • duże liczby → new BigInteger(s), .add, .max, .compareTo.
  • kilka linii odpowiedzi → osobny send dla każdej.
  • strumień → czytaj 1, odpowiadaj 1, flush.
  • nieznana długość → setSoTimeout(500) + catch (SocketTimeoutException) → przywróć setSoTimeout(0).

Kolejność na teście#

  1. Zapisz opis do pliku. 2. Sprawdź termin. 3. Zadanie po zadaniu, z pętlą powtórzeń. 4. Po każdej odpowiedzi czytaj werdykt.

Trening#

java DrillServer 7777 3 → java DrillClient localhost 7777 3 → cel: FINISHED 15/15.

Projekt — sieć proxy łącząca serwery TCP i UDP

Komendy bazowe#

GET NAMES → OK n k1 … kn · GET VALUE k → OK v/NA · SET k v → OK/NA · QUIT → (nic) · inne → NA.

Uruchomienie#

java Proxy -port P -server host port [-server host port ...] — zły parametr → błąd + exit.

Punkty#

150 (1 protokół, bez proxy) · 300 (2 protokoły, bez proxy) · 300 (1 protokół, drzewo) · 400 (2 protokoły, drzewo) · 500 (2 protokoły, cykle). Deklarujesz → musi działać wszystko albo 0.

Architektura#

  1. parametry → 2. nasłuch TCP+UDP (wątki) → 3. jeden handler komend → 4. wykrywanie + tablica kluczy → 5. przekazywanie z timeoutem → 6. protokół proxy–proxy → 7. ID + seen + TTL (cykle) → 8. QUIT do wszystkich.

Pułapki#

  • UDP do UDPServer: spacja na końcu komendy.
  • odpowiedzi: jedna linia; UDP ≤ 256 B.
  • QUIT: bez czekania na odpowiedź.
  • sprawdzaj komendy (niepełne zabijają serwer).
  • GET NAMES: unikalne nazwy + poprawny licznik.
  • timeouty wszędzie; ConcurrentHashMap.

Oddanie#

javac *.java bez pakietów · tylko Twoje .java + skrypty + „Dokumentacja (nr indeksu).pdf” · localhost · bez hardkodowanych IP/portów · GAKKO przed terminem.
