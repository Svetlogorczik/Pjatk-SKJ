💬Разговор с текстовым сервером — клиент строка за строкой

Кто говорит первым, когда прекращать чтение и как сохранить ответ в файл. Тренируемся на собственном сервере QuoteDesk — лучшая подготовка к коллоквиуму.

Коротко#

  • Текстовый протокол = разговор строками: каждое сообщение заканчивается \r\n (или \n).
  • Прежде чем писать клиента, выясни: кто говорит первым (клиент или сервер) и как узнать, что ответ закончился.
  • Есть 4 способа понять «конец ответа»: известное число строк, строка-маркер (например, END), закрытие соединения сервером (readLine() == null) или тишина (таймаут).
  • Ответ часто нужно сохранить в файл — без первой и последней строки (заголовок и подвал).
🔁Откуда задание (исходное задание с занятий, кратко)

На ćwiczeniach 5 писали нескольких клиентов, подключавшихся к серверам преподавателя: один отправлял строку с идентификатором и читал всё до закрытия соединения, сохраняя середину ответа в файл; другой должен был сначала прочитать приветствие сервера и только потом что-то отправить. Это была и тренировка перед коллоквиумом. Здесь у тебя свой тренировочный сервер (QuoteDesk), так что можно тренироваться дома.

Четыре вопроса перед написанием клиента#

  1. Кто говорит первым? Если сервер шлёт приветствие, а ты сразу читаешь «свой» ответ, всё сдвинется на одну строку. Если обе стороны ждут друг друга, программа висит.
  2. Какой формат каждой строки? Слова, пробелы, регистр букв, конец строки.
  3. Как понять, что ответ закончился? (таблица ниже)
  4. Что делать с ошибкой? Например, сервер отвечает ERR ... или закрывает соединение.

Как понять конец ответа?#

СпособКак в кодеПример
известное число строкfor (int i = 0; i < n; i++) in.readLine();«сервер пришлёт 4 числа»
число указано в заголовкепрочитай BEGIN 3, потом 3 строкиBEGIN 3 + 3 цитаты
строка-маркер концаwhile (!(line = in.readLine()).equals("END"))END
сервер закрывает соединениеwhile ((line = in.readLine()) != null)DUMP в QuoteDesk
тишина (ничего не приходит)socket.setSoTimeout(500) + catch (SocketTimeoutException e)задача 5 на коллоквиуме
🐞Частая ошибкаНе используй in.available(), чтобы определить конец сообщения ✍️ от автора

available() говорит только, сколько байт уже лежит в буфере прямо сейчас, а не пришлёт ли сервер ещё что-то. Данные из сети приходят кусками, поэтому available() == 0 может случиться посреди ответа. Программа то работает, то нет — худший вид ошибки.

Протокол QuoteDesk#

S: = сервер, C: = клиент. Каждая строка заканчивается \r\n.

Тренировочный сервер#

Многопоточный — каждый клиент получает свой поток, поэтому подключаться могут несколько человек сразу.

Клиент#

На что обратить внимание в клиенте:

  • expect("HELLO") — сначала читаем приветствие, только потом отправляем NAME.
  • Методы send / read / expect — маленький «набор инструментов», благодаря которому основной код читается как описание протокола. Каждая отправленная и полученная строка логируется — при отладке это золото.
  • Часть 1 читает до маркера END, часть 2 — до закрытия соединения (null).
  • В файл попадают только строки между маркерами: all.subList(1, all.size() - 1) пропускает первую (ALL 9) и последнюю (CLOSING).

Запуск#

  1. javac QuoteDesk.java DeskClient.java
  2. Терминал 1: java QuoteDesk 5050
  3. Терминал 2: java DeskClient localhost 5050 ola
  4. Проверь файлы quotes.txt (3 строки) и all-quotes.txt (9 строк).

Задания#

🎯Задание1. Нумерованная запись

Попроси 5 цитат и сохрани их в файл в формате 1. текст, 2. текст…

✅Показать решение

В цикле чтения до END держи счётчик: quotes.add((quotes.size() + 1) + ". " + line);, а команду поменяй на QUOTES 5.

🎯Задание2. Обработай ошибку

Отправь QUOTES 0. Что ответит сервер? Измени клиента так, чтобы после ERR он печатал понятное сообщение и завершался без исключения.

✅Показать решение

Сервер ответит ERR unknown command: QUOTES 0 (разрешены только 1–9). В клиенте: после read() проверь if (line.startsWith("ERR")) { System.out.println("Сервер сообщил об ошибке: " + line); return; }.

🎯Задание3. Новая команда протокола

Добавь на сервер команду COUNT, на которую сервер отвечает COUNT <число цитат>. Обнови таблицу протокола.

✅Показать решение

В serve: else if (cmd[0].equals("COUNT")) { reply(out, "COUNT " + QUOTES.length); } — вставь перед веткой ERR. Помни, что команда работает только после NAME (так устроено условие nick == null).

🎯Задание4. Защита от «молчащего» сервера

Что будет, если сервер никогда не пришлёт END? Защити клиента от вечного ожидания.

✅Показать решение

readLine() будет ждать вечно. Поставь socket.setSoTimeout(5000); — тогда через 5 с без данных readLine() бросит SocketTimeoutException, которое можно поймать и обработать.

Перед написанием клиента#

  1. Кто говорит первым? (проверь nc -C host port)
  2. Формат строки и конец строки (\r\n).
  3. Как понять конец ответа?
  4. Как выглядит ошибка?

5 способов понять конец ответа#

  • известное число строк → for
  • число в заголовке (BEGIN n) → прочитать n
  • маркер (END) → while (!line.equals("END"))
  • сервер закрывает → while ((line = in.readLine()) != null)
  • тишина → setSoTimeout + SocketTimeoutException

Вспомогательные методы (шаблон)#

  • send(line): out.print(line + "\r\n"); out.flush(); + лог
  • read(): readLine(), null → исключение «сервер закрыл»; лог
  • expect(prefix): read() + проверка начала

Запись в файл#

  • BufferedWriter w = new BufferedWriter(new FileWriter("out.txt"));
  • без первой и последней строки: list.subList(1, list.size() - 1)

Не делай#

  • in.available() как «конец сообщения».
  • Чтение ответа до чтения приветствия.
  • Забытый flush().
