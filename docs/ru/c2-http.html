🔎Wireshark и HTTP — читаем разговор браузера с сервером

Как перехватить HTTP-трафик в Wireshark и прочитать версию протокола, заголовки, коды статуса, условный GET (304), разбиение ответа на сегменты TCP, встроенные объекты и аутентификацию Basic.

Коротко#

  • Wireshark копирует каждый кадр, проходящий через сетевую карту, и показывает его уровень за уровнем.
  • HTTP — текстовый протокол: запрос (GET /страница HTTP/1.1 + заголовки + пустая строка) и ответ (HTTP/1.1 200 OK + заголовки + пустая строка + тело).
  • Условный GET: браузер отправляет If-Modified-Since, а сервер отвечает 304 Not Modified без тела, если файл не менялся.
  • Длинный HTTP-ответ TCP делит на много сегментов.
  • Authorization: Basic ... — это всего лишь Base64, пароль можно прочитать.
🔁Откуда задание (исходное задание с занятий, кратко)

На занятиях делается лабораторная Wireshark HTTP из учебника Kurose & Ross: перехватывается трафик браузера к нескольким простым страницам на сервере gaia.cs.umass.edu и даются ответы на вопросы о заголовках, кодах статуса, условном GET, длинных документах, картинках внутри страницы и странице с паролем. Ниже — наш собственный набор вопросов о том же самом и подсказки, где искать ответы: конкретные значения зависят от твоего перехвата.

Перед началом (из инструкции к лабораторной)#

  1. Выключи VPN — с VPN данные верхних уровней зашифрованы, и ты ничего не увидишь.
  2. Отключи HTTP/3 и QUIC в браузере — они тоже шифруют трафик (с 2025 года в большинстве браузеров включены по умолчанию).
  3. Вводи адреса, начинающиеся с http://, а не https://.
  4. Очисти кэш и историю браузера; выключи настройки «приватности», которые могут менять запросы.
  5. В поле фильтра Wireshark введи http (строчными буквами) — увидишь только HTTP-пакеты.
  6. Пропускай запросы favicon.ico — это браузер сам спрашивает иконку страницы.
💡ПодсказкаНе получается перехватить трафик вживую?

Лабораторная даёт готовые файлы перехвата (trace files, архив wireshark-traces-9e.zip на сайте авторов). Открываешь через File → Open и отвечаешь на вопросы так же.

Wireshark за 2 минуты ✍️ от автора#

В окне Wireshark три панели:

  1. Список пакетов — одна строка на кадр: номер (его даёт Wireshark, в самом пакете его нет!), время, источник, назначение, протокол, описание.
  2. Детали пакета — дерево уровней: Frame → Ethernet → IP → TCP → HTTP (это инкапсуляция из W7).
  3. Байты — сырое содержимое в hex и ASCII.

Самые полезные фильтры:

ФильтрЧто показывает
httpтолько HTTP
http.request.method == "GET"только запросы GET
http.response.code == 304только ответы 304
ip.addr == 128.119.245.12трафик к/от адреса
tcp.port == 8080трафик на порту 8080 (например, твой сервер из C3)
tcp / udp / dnsнужный протокол

Правый клик по пакету → Follow → TCP Stream — увидишь весь разговор обычным текстом (запрос красным, ответ синим).

Анатомия HTTP-сообщения ✍️ от автора#

Пример (придуманный, но ровно в формате настоящего):

ЭлементГдеЧто значит
GET /lab/hello.html HTTP/1.1строка запросаметод, путь, версия HTTP клиента
Hostзаголовокимя сервера (в HTTP/1.1 обязателен)
Accept-Languageзаголовокязыки, которые принимает браузер (q = приоритет)
If-Modified-Sinceзаголовок«пришли, только если изменилось после этой даты»
пустая строкапосле заголовковконец заголовков — без неё сервер ждёт вечно
HTTP/1.1 200 OKстрока статусаверсия HTTP сервера, код, описание
Last-Modifiedзаголовоккогда файл изменили на сервере
Content-Lengthзаголовоксколько байт тела (без заголовков)

Главные коды статуса:

КодЗначение
200 OKвсё хорошо, тело в ответе
301 Moved Permanentlyресурс переехал (заголовок Location)
304 Not Modifiedне изменилось — используй копию из кэша, тела нет
400 Bad Requestсервер не понял запрос (например, неверный формат)
401 Unauthorizedнужен вход (заголовок WWW-Authenticate)
404 Not Foundтакого ресурса нет
405 Method Not Allowedметод (например, POST) запрещён

Часть A — простой GET и ответ#

Открой простую короткую страницу (например, первый файл лабораторной) и найди два пакета: GET и ответ.

🎯ЗаданиеВопросы A1–A7
  1. Какую версию HTTP объявляет браузер, а какую сервер?
  2. Как называется заголовок со списком предпочитаемых языков и какие языки в нём?
  3. Какой IP-адрес у твоего компьютера, а какой у сервера?
  4. Какой код и описание статуса вернул сервер?
  5. Когда файл последний раз изменялся на сервере?
  6. Сколько байт содержимого прислал сервер?
  7. Видно ли в сырых байтах какой-то заголовок, которого нет в списке пакетов?
🔦Показать подсказкуГде искать
  1. Строка запроса в пакете GET (последнее слово) и строка статуса в ответе (первое слово).
  2. В GET: Accept-Language.
  3. Уровень IP пакета GET: Source = твой компьютер, Destination = сервер. В ответе наоборот.
  4. Строка статуса ответа, например 200 OK.
  5. Заголовок Last-Modified в ответе. Внимание: сервер лабораторной каждую минуту ставит дату изменения «сейчас» — поэтому в инструкции просят подождать больше минуты перед перехватом.
  6. Заголовок Content-Length (длина только тела). Не путай с длиной сегмента TCP (тело + HTTP-заголовки).
  7. Сравни дерево HTTP с панелью байтов — Wireshark обычно показывает все заголовки; ответ «лишних не вижу» тоже верный, если так и есть.

Часть B — условный GET (304)#

Браузеры хранят копии страниц в кэше. Когда ты открываешь ту же страницу снова, браузер спрашивает сервер: «изменилось ли с…?».

  1. Очисти кэш, запусти перехват.
  2. Открой страницу и сразу же обнови её (или введи адрес ещё раз).
  3. Останови перехват, фильтр http.
🎯ЗаданиеВопросы B1–B4
  1. Есть ли заголовок If-Modified-Since в первом GET?
  2. Содержит ли первый ответ содержимое файла? Как это понять?
  3. Есть ли If-Modified-Since во втором GET? Какая там дата и откуда браузер её взял?
  4. Какой код статуса у второго ответа и есть ли в нём тело?
✅Показать решениеОбразцовые ответы (даты зависят от перехвата)
  1. Нет — у браузера ещё нет копии (кэш был пуст).
  2. Да — код 200, Content-Length > 0, и в Wireshark видна секция Line-based text data с HTML.
  3. Да — дата совпадает с Last-Modified из первого ответа: браузер запомнил её вместе с копией.
  4. 304 Not Modified — без тела; браузер показывает копию из кэша. (Замечание из инструкции: Chrome охотно шлёт If-Modified-Since, а Firefox и Safari бывают капризны.)

Часть C — длинный документ#

Если HTML-файл длинный (в лабораторной около 4500 байт), один HTTP-ответ не помещается в один сегмент TCP. TCP делит его на несколько сегментов, а Wireshark помечает их как «TCP segment of a reassembled PDU».

🎯ЗаданиеВопросы C1–C4
  1. Сколько запросов GET отправил браузер? В каком пакете (номер из списка) GET за длинным файлом?
  2. В каком пакете строка статуса ответа?
  3. Какие там код и описание?
  4. Сколько сегментов TCP с данными понадобилось на весь ответ?
🔦Показать подсказкуГде искать

Очисти фильтр (чтобы видеть и сегменты TCP). В пакете с HTTP-ответом раскрой секцию «[N Reassembled TCP Segments]» — Wireshark напишет, сколько сегментов он собрал и из каких пакетов. Строка статуса находится в первом из них, но Wireshark показывает HTTP-ответ у последнего.

Часть D — страница со встроенными объектами#

Страница может содержать картинки с других серверов. В HTML есть только адреса (URL) картинок, поэтому браузер отправляет за ними отдельные запросы.

🎯ЗаданиеВопросы D1–D2
  1. Сколько запросов GET отправил браузер и на какие IP-адреса?
  2. Картинки скачивались по очереди (последовательно) или параллельно? Как проверить?
🔦Показать подсказкуКак проверить

Смотри на колонку Time и на исходные порты TCP: если второй GET ушёл раньше, чем пришёл ответ на первый, и по другому TCP-соединению (другой исходный порт) — загрузка параллельная. Если каждый GET ждёт окончания предыдущего — последовательная.

Часть E — страница с паролем (HTTP Basic)#

В лабораторной есть страница, для которой нужен вход (логин и пароль даны в инструкции к лабораторной).

🎯ЗаданиеВопросы E1–E3
  1. Что сервер отвечает на первый GET (код и описание)?
  2. Какое новое поле появляется во втором GET (после ввода пароля)?
  3. Раскодируй значение этого поля. Что видишь?
✅Показать решениеОбразцовые ответы
  1. 401 Unauthorized (с заголовком WWW-Authenticate, который просит войти).
  2. Authorization: Basic <строка>.
  3. Строка — это Base64 от текста логин:пароль. Это не шифрование — любой, кто перехватит пакет, его раскодирует (см. W6).
