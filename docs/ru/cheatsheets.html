W1Что такое Интернет и что такое протокол?

Определения (выучить)#

  • Хост / конечная система — устройство на краю сети, запускает приложения.
  • Коммутатор пакетов — роутер или switch, пересылает пакеты.
  • Канал — оптоволокно, медь, радио, спутник; есть пропускная способность в бит/с.
  • Сеть — устройства + роутеры + каналы под управлением одной организации.
  • Интернет — сеть сетей, соединённые провайдеры ISP.
  • Протокол — формат + порядок + действия для сообщений.
  • RFC — документ со стандартом; IETF — кто их пишет.

Два взгляда на Интернет#

  1. «Болты и гайки»: хосты, роутеры/свитчи, каналы, сети.
  2. «Услуга»: инфраструктура для приложений + программный интерфейс (в Java: сокеты Socket, DatagramSocket).

Как описать протокол по шагам (проект, коллоквиум)#

  1. Перечисли участников (клиент, сервер, proxy).
  2. Для каждого сообщения дай точный формат (слова, пробелы, \r\n).
  3. Опиши порядок: кто начинает, что на что отвечает.
  4. Опиши действия и ошибки: неизвестная команда, нет ответа.
  5. Добавь пример разговора (как в RFC).

Среда#

  • Витая пара кат. 5: 100 Мбит/с–1 Гбит/с; кат. 6: 10 Гбит/с.
  • Коаксиал: много каналов, сотни Мбит/с на канал.
  • Оптоволокно: 10–100+ Гбит/с, не боится помех.
  • Радио: half-duplex, отражения, препятствия, интерференция.

Задержка передачи — по шагам#

  1. LLL в байтах → ×8\times 8×8 → биты.
  2. RRR в Мбит/с → ×106\times 10^6×106 → бит/с.
  3. dtrans=L/Rd_{trans} = L / Rdtrans​=L/R [с].
  4. Результат ×1000 → мс.

Пример: 1500 B при 100 Мбит/с → 12 000 / 10⁸ = 0,12 мс.

W3Ядро сети — коммутация пакетов и коммутация каналов

Формулы#

  • Один канал: dtrans=L/Rd_{trans} = L/Rdtrans​=L/R.
  • Store-and-forward, 1 пакет, NNN каналов: N⋅L/RN \cdot L/RN⋅L/R.
  • PPP пакетов, NNN каналов: (N+P−1)⋅L/R(N + P - 1)\cdot L/R(N+P−1)⋅L/R.
  • TDM: скорость линии =R/число слотов= R / \text{число слотов}=R/число слотов.
  • Каналы: число пользователей =⌊C/r⌋= \lfloor C / r \rfloor=⌊C/r⌋.
  • Пакеты: P(X>k)=1−∑i=0k(Ni)pi(1−p)N−iP(X > k) = 1 - \sum_{i=0}^{k}\binom{N}{i}p^i(1-p)^{N-i}P(X>k)=1−∑i=0k​(iN​)pi(1−p)N−i.

Факты#

  • Роутер: весь пакет должен прийти, прежде чем уйдёт дальше.
  • Поступление > выход → очередь; полный буфер → потеря.
  • Forwarding = локально (таблица), routing = глобально (алгоритмы).
  • Каналы: бронь, гарантия, простои; FDM (полосы), TDM (слоты).
  • Пример лекции: 1 Гбит/с, 100 Мбит/с, 10% → каналы 10 человек, пакеты 35 человек при P ≈ 0,0004.

«Файл через TDM-канал» по шагам#

  1. Скорость линии = R / число слотов.
  2. Время = размер файла [бит] / скорость линии.
  3. Прибавь время установки соединения.

W4Структура Интернета — «сеть сетей»

Иерархия (снизу вверх)#

  1. Access ISP — провайдер доступа (дом, фирма, вуз).
  2. Regional ISP — собирает трафик местных провайдеров.
  3. Tier-1 ISP — глобальные (Level 3, Sprint, AT&T, NTT).
  4. Content provider networks — Google, Microsoft, Akamai, Facebook: свои сети, обходят tier-1.

Ключевые слова#

  • Клиент–поставщик: экономическое соглашение, клиент платит за транзит.
  • IXP: точка обмена трафиком многих сетей.
  • Пиринг: прямое соединение двух сетей.
  • POP: точка присутствия сети провайдера.
  • Структура — результат экономики и политики, а не единого плана.

Подсчёт каналов «каждый с каждым»#

  • N(N−1)/2N(N-1)/2N(N−1)/2, например 1000 сетей → 499 500 каналов → O(N2)O(N^2)O(N2), не масштабируется.

Формулы#

  • Throughput =min⁡(Rs,Rc,R/n)= \min(R_s, R_c, R/n)=min(Rs​,Rc​,R/n); время скачивания =F/throughput= F / \text{throughput}=F/throughput
  • Путь из NNN каналов: N⋅dnodalN \cdot d_{nodal}N⋅dnodal​ (учебник)

Задача «посчитай задержку» по шагам#

  1. Выпиши данные и переведи единицы: B → бит (×8), Мбит/с → бит/с (×10⁶), км → м (×1000).
  2. dtrans=L/Rd_{trans} = L/Rdtrans​=L/R.
  3. dprop=d/sd_{prop} = d/sdprop​=d/s.
  4. Добавь dprocd_{proc}dproc​ и dqueued_{queue}dqueue​ (если даны; обычно 0).
  5. Умножь на число каналов (store-and-forward).
  6. Результат в мс (×1000).

Караван#

  • 10 машин × 12 с = 120 с + 100 км / 100 км/ч = 60 мин → 62 мин.
  • 1000 км/ч, 1 мин/машина → первая машина у 2-го пункта через 7 мин, 3 машины ещё ждут.

traceroute#

  • TTL = i → отвечает роутер i; 3 измерения на роутер; * * * = нет ответа.
  • Windows: tracert, Linux/macOS: traceroute.

W8История Интернета — от ARPAnet до смартфонов

Хронология (минимум к экзамену)#

  • 1961 Клейнрок — теория очередей, пакеты эффективны.
  • 1964 Бэрэн — пакеты в военных сетях.
  • 1967 ARPA задумывает ARPAnet; 1969 первый узел.
  • 1970 ALOHAnet (Гавайи, спутник).
  • 1972 демо ARPAnet, NCP, первая почта, 15 узлов.
  • 1974 Серф и Кан — internetworking.
  • 1976 Ethernet (Xerox PARC).
  • 1979 ARPAnet: 200 узлов.
  • 1982 SMTP; 1983 TCP/IP + DNS; 1985 FTP; 1988 контроль перегрузки TCP.
  • 1991 коммерческое использование NSFnet; 1995 NSFnet закрыт.
  • ~1990 веб: HTML, HTTP (Бернерс-Ли); 1994 Mosaic → Netscape.
  • 2007 iPhone; 2017 ~18 млрд устройств.

Принципы Серфа и Кана#

  1. Минимализм, автономия (без изменений внутри сетей).
  2. Best effort.
  3. Маршрутизация без состояния.
  4. Децентрализованное управление.

C1Первая распределённая программа — эстафета процессов по кольцу

Понятия#

  • Порт = «дверь» процесса (0–65535). Сокет = IP + порт.
  • localhost = 127.0.0.1 = этот компьютер.
  • Сервер: new ServerSocket(port) → accept() (ждёт).
  • Клиент: new Socket(host, port) → подключается.
  • Порт клиента случайный (эфемерный).

Порядок запуска#

  1. Сначала процессы, которые слушают.
  2. Потом тот, кто начинает отправлять.
  3. Или: повторяй подключение каждые несколько сотен мс.

Конфигурация#

  • Properties p = new Properties(); p.load(new FileInputStream(файл));
  • p.getProperty("listenPort") → Integer.parseInt(...).
  • Никогда не хардкодь IP и порты.

Ошибки#

  • Connection refused → никто не слушает.
  • Address already in use → порт занят.
  • «Висит» → ждёт в accept()/readLine(); проверь flush().
  • Кто занял порт: netstat -ano | findstr PORT / ss -ltnp / lsof -i :PORT.

C3TCP-сокеты в Java — свой мини HTTP-сервер и клиент

TCP-сервер — каркас#

  1. ServerSocket ss = new ServerSocket(port);
  2. Socket s = ss.accept(); (ждёт)
  3. BufferedReader in = new BufferedReader(new InputStreamReader(s.getInputStream(), UTF_8));
  4. PrintWriter out = new PrintWriter(new OutputStreamWriter(s.getOutputStream(), UTF_8));
  5. прочитать → обработать → out.print(...); out.flush();
  6. s.close(); (и снова к accept())

TCP-клиент — каркас#

  1. Socket s = new Socket(host, port);
  2. отправить строки + flush()
  3. читать while ((line = in.readLine()) != null) (если сервер закрывает) или до маркера конца
  4. s.close();

C4Разговор с текстовым сервером — клиент строка за строкой

Перед написанием клиента#

  1. Кто говорит первым? (проверь nc -C host port)
  2. Формат строки и конец строки (\r\n).
  3. Как понять конец ответа?
  4. Как выглядит ошибка?

5 способов понять конец ответа#

  • известное число строк → for
  • число в заголовке (BEGIN n) → прочитать n
  • маркер (END) → while (!line.equals("END"))
  • сервер закрывает → while ((line = in.readLine()) != null)
  • тишина → setSoTimeout + SocketTimeoutException

Вспомогательные методы (шаблон)#

  • send(line): out.print(line + "\r\n"); out.flush(); + лог
  • read(): readLine(), null → исключение «сервер закрыл»; лог
  • expect(prefix): read() + проверка начала

Запись в файл#

  • BufferedWriter w = new BufferedWriter(new FileWriter("out.txt"));
  • без первой и последней строки: list.subList(1, list.size() - 1)

Не делай#

  • in.available() как «конец сообщения».
  • Чтение ответа до чтения приветствия.
  • Забытый flush().

C5TCP и UDP вместе — поток против датаграмм

UDP — рецепт#

  • Сервер: DatagramSocket s = new DatagramSocket(port);
  • Клиент: DatagramSocket s = new DatagramSocket(); s.setSoTimeout(1000);
  • Отправить: byte[] b = text.getBytes(UTF_8); s.send(new DatagramPacket(b, b.length, InetAddress.getByName(host), port));
  • Принять: DatagramPacket p = new DatagramPacket(new byte[1500], 1500); s.receive(p);
  • Текст: new String(p.getData(), 0, p.getLength(), UTF_8)
  • Ответить: new DatagramPacket(b, b.length, p.getAddress(), p.getPort())

Ловушки#

  • всегда getLength();
  • новый пакет для каждого receive (или setLength);
  • маленький буфер = обрезанное сообщение без ошибки;
  • TCP-порт и UDP-порт с одним номером — это два разных порта.

RTT#

long t = System.nanoTime(); send...; receive...; (System.nanoTime() - t) / 1e6 = мс.

C6DNS изнутри — запрос, собранный вручную, байт за байтом

Заголовок (12 B)#

ID(2) · FLAGS(2) · QDCOUNT(2) · ANCOUNT(2) · NSCOUNT(2) · ARCOUNT(2) — big-endian.

Флаги#

QR(15) · OPCODE(14–11) · AA(10) · TC(9) · RD(8) · RA(7) · Z(6–4) · RCODE(3–0).

  • запрос: 0x0100 (RD=1); типичный ответ: 0x8180; NXDOMAIN: RCODE = 3.

Сборка запроса по шагам#

  1. writeShort(id), writeShort(0x0100), writeShort(1), 3× writeShort(0).
  2. Для каждой метки: writeByte(длина) + байты букв; в конце writeByte(0).
  3. writeShort(QTYPE) (A=1, NS=2, CNAME=5, MX=15, AAAA=28), writeShort(1) (IN).
  4. Отправить по UDP на порт 53, буфер ответа 512 B, таймаут.

Разбор ответа по шагам#

  1. Проверь ID, потом флаги и RCODE.
  2. Прочитай счётчики.
  3. Пропусти вопрос: имя + 4 байта.
  4. Для каждой записи: NAME (осторожно с C0 xx), TYPE, CLASS, TTL (4 B), RDLENGTH, RDATA.
  5. A → 4 байта & 0xFF через точки.

Ловушки#

  • byte со знаком → & 0xFF.
  • Указатель: b >= 0xC0, смещение = ((b1 & 0x3F) << 8) | b2; после указателя имя кончается.

nslookup / Wireshark#

  • nslookup имя, -type=NS, -type=MX, nslookup IP (обратный).
  • «Non-authoritative» = из кэша.
  • Фильтр dns, udp.port == 53; очистка: ipconfig /flushdns.

C7TCP под лупой — номера последовательности, RTT, окно и slow start в Wireshark

Рукопожатие#

SYN (seq = x) → SYN+ACK (seq = y, ack = x+1) → ACK (ack = y+1).

seq / ack#

  • следующий seq = seq + длина данных;
  • ack = следующий ожидаемый байт; ACK накопительный;
  • SYN и FIN расходуют по 1 номеру;
  • Wireshark: относительные номера (сырые — в отдельном поле).

Формулы#

  • Est=0,875⋅Est+0,125⋅Sample\text{Est} = 0{,}875\cdot\text{Est} + 0{,}125\cdot\text{Sample}Est=0,875⋅Est+0,125⋅Sample (старт: Est = 1-я выборка)
  • Dev=0,75⋅Dev+0,25⋅∣Sample−Est∣\text{Dev} = 0{,}75\cdot\text{Dev} + 0{,}25\cdot|\text{Sample} - \text{Est}|Dev=0,75⋅Dev+0,25⋅∣Sample−Est∣; Timeout=Est+4⋅Dev\text{Timeout} = \text{Est} + 4\cdot\text{Dev}Timeout=Est+4⋅Dev
  • окно = Window Size Value × множитель
  • пропускная способность = байты / время (×8 → бит/с)

Wireshark#

  • фильтр tcp, tcp.flags.syn == 1, tcp.analysis.retransmission, tcp.stream eq 0;
  • Statistics → TCP Stream Graphs → Round Trip Time / Time-Sequence (Stevens);
  • сырые seq: Preferences → Protocols → TCP → снять Relative sequence numbers.

Slow start vs congestion avoidance#

  • ×2 за RTT → slow start; +1 MSS за RTT → congestion avoidance;
  • промежуток между флотилиями ≈ RTT.

Практический коллоквиум — тренировка с сервером DrillServer

Шаблон клиента (ядро)#

  • Socket s = new Socket(host, port);
  • in = new BufferedReader(new InputStreamReader(s.getInputStream(), UTF_8));
  • out = new PrintWriter(new OutputStreamWriter(s.getOutputStream(), UTF_8));
  • send(x): out.print(x + "\r\n"); out.flush(); + лог
  • read(): readLine(); null → исключение; лог

Шаблоны задач#

  • 1 строка, много чисел → split("\\s+") + Long.parseLong.
  • N строк → for (i < N) list.add(read()).
  • большие числа → new BigInteger(s), .add, .max, .compareTo.
  • несколько строк ответа → отдельный send на каждую.
  • поток → прочитал 1, ответил 1, flush.
  • неизвестная длина → setSoTimeout(500) + catch (SocketTimeoutException) → вернуть setSoTimeout(0).

Порядок на тесте#

  1. Сохрани описание в файл. 2. Проверь срок. 3. Задача за задачей, с циклом повторений. 4. После каждого ответа читай вердикт.

Тренировка#

java DrillServer 7777 3 → java DrillClient localhost 7777 3 → цель: FINISHED 15/15.

Проект — сеть proxy, соединяющая TCP- и UDP-серверы

Базовые команды#

GET NAMES → OK n k1 … kn · GET VALUE k → OK v/NA · SET k v → OK/NA · QUIT → (ничего) · другое → NA.

Запуск#

java Proxy -port P -server host port [-server host port ...] — неверный параметр → ошибка + exit.

Баллы#

150 (1 протокол, без proxy) · 300 (2 протокола, без proxy) · 300 (1 протокол, дерево) · 400 (2 протокола, дерево) · 500 (2 протокола, циклы). Заявил → должно работать всё, иначе 0.

Архитектура#

  1. параметры → 2. слушатели TCP+UDP (потоки) → 3. один обработчик команд → 4. определение + таблица ключей → 5. пересылка с таймаутами → 6. протокол proxy–proxy → 7. ID + seen + TTL (циклы) → 8. QUIT всем.

Ловушки#

  • UDP к UDPServer: пробел в конце команды.
  • ответы: одна строка; UDP ≤ 256 B.
  • QUIT: не ждать ответа.
  • проверяй команды (неполные убивают сервер).
  • GET NAMES: уникальные имена + верный счётчик.
  • таймауты везде; ConcurrentHashMap.
