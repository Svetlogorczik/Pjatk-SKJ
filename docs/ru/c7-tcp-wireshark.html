🦈TCP под лупой — номера последовательности, RTT, окно и slow start в Wireshark

Коротко#

  • TCP-соединение начинается в 3 шага: SYN → SYN+ACK → ACK.
  • TCP нумерует байты, а не пакеты: seq = номер первого байта в сегменте, ack = номер следующего ожидаемого байта.
  • SampleRTT = время от отправки сегмента до прихода его ACK. EstimatedRTT — сглаженное среднее: (1−α)⋅EstimatedRTT+α⋅SampleRTT(1-\alpha)\cdot\text{EstimatedRTT} + \alpha\cdot\text{SampleRTT}(1−α)⋅EstimatedRTT+α⋅SampleRTT, α=0,125\alpha = 0{,}125α=0,125.
  • Окно получателя (rwnd) говорит отправителю, сколько байт ещё поместится в буфер получателя.
  • Пропускная способность = переданные байты / время. Slow start: окно растёт ×2 каждый RTT («флотилии» пакетов).
🔁Откуда задание (исходное задание с занятий, кратко)

На занятиях делается лабораторная Wireshark TCP из учебника Kurose & Ross: большой текстовый файл (около 150 КБ) отправляется методом HTTP POST на сервер лабораторной, трафик перехватывается, и нужно ответить на вопросы об адресах и портах, номерах SYN/SYN-ACK, сегменте с POST, RTT и EstimatedRTT, длинах сегментов, окне получателя, повторных передачах, подтверждениях, пропускной способности и фазах контроля перегрузки (график Стивенса). Ниже — наши вопросы и числовые примеры, а в каждом вопросе подсказка, где искать ответ.

Подготовка (из инструкции к лабораторной)#

  1. Скачай текстовый файл из лабораторной (ссылка в инструкции) и сохрани его на диск.
  2. Открой страницу лабораторной с формой загрузки файла, выбери файл, пока не отправляй.
  3. Запусти перехват в Wireshark.
  4. Нажми кнопку отправки — файл уйдёт на сервер методом POST.
  5. Останови перехват и введи фильтр tcp.

Как и для HTTP — у лабораторной есть готовый файл перехвата (tcp-wireshark-trace1-1 в архиве wireshark-traces-9e.zip).

RTT и EstimatedRTT#

SampleRTT для сегмента = (время прихода ACK, который его подтверждает) − (время отправки сегмента). Одна выборка «скачет», поэтому TCP считает взвешенное среднее:

EstimatedRTT=(1−α)⋅EstimatedRTT+α⋅SampleRTT,α=0,125\text{EstimatedRTT} = (1-\alpha)\cdot\text{EstimatedRTT} + \alpha\cdot\text{SampleRTT}, \qquad \alpha = 0{,}125EstimatedRTT=(1−α)⋅EstimatedRTT+α⋅SampleRTT,α=0,125

В лабораторной принимается, что первое EstimatedRTT = первому измеренному RTT.

Окно получателя и масштабирование#

Поле window в сегменте от получателя говорит отправителю, сколько байт ещё можно отправить без ожидания ACK (управление потоком). Если в SYN договорились о window scale, настоящее значение:

окно [B]=Window Size Value⋅множитель\text{окно [B]} = \text{Window Size Value} \cdot \text{множитель}окно [B]=Window Size Value⋅множитель

Пример: Window Size Value: 501, множитель 128 → 501⋅128=64 128501 \cdot 128 = 64\,128501⋅128=64128 B. Wireshark показывает это как Calculated window size. Если окно никогда не падает (почти) до нуля, получатель не тормозит отправителя.

Повторные передачи и подтверждения#

  • Повторная передача (retransmission) = сегмент с тем же seq, отправленный снова. Wireshark помечает его [TCP Retransmission]; фильтр: tcp.analysis.retransmission.
  • Отложенный ACK: получатель часто подтверждает каждый второй сегмент (ack растёт примерно на 2 × MSS). Вычти соседние значения ack, чтобы увидеть, сколько байт подтверждает один ACK.

Пропускная способность соединения#

пропускная способность=число переданных байтвремя\text{пропускная способность} = \frac{\text{число переданных байт}}{\text{время}}пропускная способность=времячисло переданных байт​

Первый сегмент с данными отправлен в t=0,0245t = 0{,}0245t=0,0245 с, последний ACK пришёл в t=0,2009t = 0{,}2009t=0,2009 с, передано 153 000153\,000153000 B.

  1. Время: 0,2009−0,0245=0,17640{,}2009 - 0{,}0245 = 0{,}17640,2009−0,0245=0,1764 с.
  2. Пропускная способность: 153 000/0,1764≈867 347153\,000 / 0{,}1764 \approx 867\,347153000/0,1764≈867347 B/с ≈0,87\approx 0{,}87≈0,87 МБ/с.

Число байт проще всего взять как разницу номеров: ack последнего подтверждения − seq первого сегмента с данными.

Контроль перегрузки: slow start и congestion avoidance#

  • Slow start (медленный старт): вначале окно перегрузки (cwnd) удваивается каждый RTT — отправитель шлёт «флотилию» из 2, 4, 8… сегментов и ждёт ACK.
  • Congestion avoidance (избегание перегрузки): после порога окно растёт линейно — на 1 MSS за RTT.
  • На графике Statistics → TCP Stream Graphs → Time-Sequence (Stevens) каждая точка — отправленный сегмент; точки, стоящие вертикально друг над другом, — флотилия, отправленная подряд.
  • Промежуток между флотилиями ≈ RTT (отправитель ждёт подтверждений).
✍️Добавлено автором сайта — этого нет в лекцииКак узнать фазу по графику?

Посчитай сегменты в соседних флотилиях. 2 → 4 → 8 → 16 — это slow start. То же число или +1 за RTT — congestion avoidance. Если флотилии всё время одного размера, ограничением может быть окно получателя или само приложение — при маленькой передаче (150 КБ) TCP часто даже не успевает выйти из slow start.

🎯ЗаданиеВопросы T1–T10
  1. Какой IP-адрес и порт у клиента, а какой у сервера?
  2. Какой сырой номер последовательности у сегмента SYN? Как понять, что это SYN? Сообщает ли клиент о поддержке SACK?
  3. Какой номер последовательности у SYN-ACK и какое в нём значение ack? Откуда сервер его взял?
  4. В каком сегменте начало POST и сколько в нём байт данных? Поместился ли весь файл в один сегмент?
  5. Измерь SampleRTT для первых двух сегментов с данными и посчитай EstimatedRTT после второго.
  6. Какова длина (заголовки + данные) первых четырёх сегментов с данными?
  7. Какое наименьшее окно объявляет сервер в начале? Ограничивало ли окно отправителя?
  8. Есть ли повторные передачи? Как ты это проверил?
  9. Сколько байт обычно подтверждает один ACK? Видно ли ACK на каждый второй сегмент?
  10. Какая была пропускная способность соединения? Как ты её посчитал?
🔦Показать подсказкуГде искать
  1. Уровень IP + TCP любого сегмента от клиента (у HTTP-сервера порт 80).
  2. Поле Sequence Number (raw); флаг SYN = 1; в опциях TCP ищи SACK permitted.
  3. ack в SYN-ACK = seq из SYN + 1.
  4. Ищи текст «POST» в панели байтов; длина данных = TCP Segment Len; файл > 150 КБ, поэтому не поместится (MSS ≈ 1460 B).
  5. Колонка Time: (время ACK, у которого ack ≥ конец сегмента) − (время отправки сегмента); затем формула с α = 0,125 — или калькулятор выше.
  6. Frame length или TCP Segment Len + заголовки; в перехвате лабораторной сегменты < 1480 B, потому что у IP лимит 1500 B, а заголовки TCP/IP занимают минимум 40 B.
  7. Window Size Value × множитель (или Calculated window size) в сегментах от сервера.
  8. Фильтр tcp.analysis.retransmission или поиск повторного seq.
  9. Разницы соседних значений ack от сервера.
  10. Байты / время — см. пример выше.

Рукопожатие#

SYN (seq = x) → SYN+ACK (seq = y, ack = x+1) → ACK (ack = y+1).

seq / ack#

  • следующий seq = seq + длина данных;
  • ack = следующий ожидаемый байт; ACK накопительный;
  • SYN и FIN расходуют по 1 номеру;
  • Wireshark: относительные номера (сырые — в отдельном поле).

Формулы#

  • Est=0,875⋅Est+0,125⋅Sample\text{Est} = 0{,}875\cdot\text{Est} + 0{,}125\cdot\text{Sample}Est=0,875⋅Est+0,125⋅Sample (старт: Est = 1-я выборка)
  • Dev=0,75⋅Dev+0,25⋅∣Sample−Est∣\text{Dev} = 0{,}75\cdot\text{Dev} + 0{,}25\cdot|\text{Sample} - \text{Est}|Dev=0,75⋅Dev+0,25⋅∣Sample−Est∣; Timeout=Est+4⋅Dev\text{Timeout} = \text{Est} + 4\cdot\text{Dev}Timeout=Est+4⋅Dev
  • окно = Window Size Value × множитель
  • пропускная способность = байты / время (×8 → бит/с)

Wireshark#

  • фильтр tcp, tcp.flags.syn == 1, tcp.analysis.retransmission, tcp.stream eq 0;
  • Statistics → TCP Stream Graphs → Round Trip Time / Time-Sequence (Stevens);
  • сырые seq: Preferences → Protocols → TCP → снять Relative sequence numbers.

Slow start vs congestion avoidance#

  • ×2 за RTT → slow start; +1 MSS за RTT → congestion avoidance;
  • промежуток между флотилиями ≈ RTT.
