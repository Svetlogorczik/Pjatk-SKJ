Проект (набор 2025/26)#

  • Полный правильный проект стоит 500 баллов; уровни: 150 / 300 / 300 / 400 / 500 (подробности в Проекте).
  • Проект заявляется на конкретное число баллов и проверяется только на него — если не выполнены все требования для этого числа, будет 0.
  • Java 8, только стандартные классы; файлы без пакетов; компиляция javac *.java; тесты на localhost.
  • Сдаёшь в GAKKO: свои .java, по желанию скрипты, «Dokumentacja (номер индекса).pdf» (обязательное условие оценки).
  • Срок в спецификации: 19.12.2025, 23:55 (преподаватель группы мог его изменить).
  • Антиплагиат: «сплагиаченные» проекты не проверяются, за плагиат — отрицательные баллы. Преподаватель прямо пишет: неважно, кто был автором — однокурсник, ИИ или StackOverflow, — важна самостоятельная работа.

Практический коллоквиум (набор 2025/26)#

  • Подключаешься к серверу преподавателя, логинишься, получаешь пароль и описание задач.
  • 5 задач, каждую нужно выполнить 5 раз; сервер сразу оценивает ответы.
  • В описании было время окончания теста (в 2025/26: 11.01.2026, 12:45) — изменения после него не учитываются.

  • Лабораторные Kurose & Ross: HTTP, DNS, TCP — ответы на вопросы по собственному перехвату трафика (или по готовым файлам trace).

Чего в материалах НЕТ — спроси преподавателя#

В файлах нет информации о:

  • шкале оценок и пороге зачёта (сколько баллов на 3,0 / 5,0),
  • весе коллоквиума по сравнению с проектом,
  • том, есть ли экзамен / тест по лекциям и как он выглядит,
  • правилах посещаемости и пересдач.

Я это не придумываю — проверь силлабус, GAKKO или спроси преподавателя на первых занятиях. Если тест по лекциям есть, пригодятся кнопка Конспект в каждой теме W1–W8 и страница Все конспекты.

Предлагаемый план семестра ✍️ от автора#

Даты прошлого года подсказывают примерно такой ритм: ćwiczenia с октября, проект до середины декабря, коллоквиум в январе. Исходя из этого предлагаю:

  1. Октябрь — лекции W1–W8 (1–2 темы в неделю) + C1, C2, C3. Установи JDK и Wireshark (Старт).
  2. Ноябрь — C4, C5, C6, C7. Начни тренироваться с DrillServer — раз в неделю, на время.
  3. Как только опубликуют спецификацию проекта — сразу делай этап на 150 баллов, потом следующие. Документацию пиши параллельно, а не в последнюю ночь.
  4. За неделю до срока проекта — тесты на другом компьютере, javac *.java в пустой папке, PDF, отправка в GAKKO.
  5. Перед коллоквиумом — 2–3 полные тренировки DrillServer с 5 повторениями; готовый шаблон клиента.

Чек-лист перед сдачей проекта ✍️ от автора#

  • в папке только мои файлы .java, скрипты и PDF (без .class, без проекта IntelliJ, без выданных серверов/клиентов),
  • ни в одном файле нет строки package ...,
  • javac *.java в пустой папке компилируется без ошибок (лучше javac --release 8 *.java),
  • нет захардкоженных IP-адресов, портов, путей,
  • работают все требования для заявленного числа баллов,
  • PDF назван с номером индекса и содержит полное описание протокола,
  • в PDF заполнена табличка из шаблона (автор, индекс, баллы, тестовый скрипт),
  • отправлено в GAKKO до срока.
