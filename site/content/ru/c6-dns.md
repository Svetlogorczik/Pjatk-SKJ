## Коротко

- **DNS** переводит имена (например, `pjwstk.edu.pl`) в IP-адреса. Запросы обычно идут **по UDP на порт 53**.
- DNS-сообщение = **заголовок 12 байт** + секция **вопросов** + секции **ответов**, **авторитетная** и **дополнительная**.
- Доменное имя записывается **метками**: `07 example 03 com 00`.
- В ответах имена часто **сжаты**: два байта `C0 0C` = «имя, как по смещению 12».
- В Java `byte` со знаком (−128…127) — всегда делай **`& 0xFF`**.

:::origin
На ćwiczeniach 6 DNS-запрос был записан в программе готовым массивом байт (для одного конкретного домена), отправлялся по UDP на публичный DNS-сервер на порт 53, а ответ нужно было разобрать на поля: ID, флаги, счётчики, имя, тип, класс, TTL и IP-адрес. Плюс лабораторная Wireshark DNS (nslookup, кэш DNS, отслеживание запросов). Наша версия **сама собирает** запрос для любого домена и типа, поддерживает сжатие имён и несколько типов записей.
:::

## Что делает DNS? [[own]]

Компьютеры знают IP-адреса, людям удобнее имена. Когда ты вводишь `www.example.com`:

:::steps
1. Твой компьютер проверяет **свой кэш DNS** — может, ответ уже известен.
2. Если нет, спрашивает **локальный DNS-сервер** (провайдера или, например, `8.8.8.8`).
3. Локальный сервер при необходимости спрашивает **корневой** → **TLD** (`.com`) → **авторитетный** сервер для `example.com` и запоминает результат на время **TTL**.
4. Твой компьютер получает ответ — с точки зрения клиента это один вопрос и один ответ.
:::

Типы записей, которые встретятся:

| Тип | Код | Что содержит |
|---|---|---|
| **A** | 1 | адрес IPv4 |
| **NS** | 2 | имя авторитетного сервера домена |
| **CNAME** | 5 | «это псевдоним, настоящее имя…» |
| **SOA** | 6 | информация о зоне (часто в ответе «такого имени нет») |
| **MX** | 15 | почтовый сервер (с приоритетом) |
| **AAAA** | 28 | адрес IPv6 |

## Формат DNS-сообщения

### Заголовок — 12 байт

| Байты | Поле | Значение |
|---|---|---|
| 0–1 | **ID** | номер запроса; у ответа **тот же** ID |
| 2–3 | **Flags** | флаги (ниже) |
| 4–5 | **QDCOUNT** | число вопросов |
| 6–7 | **ANCOUNT** | число записей ответа |
| 8–9 | **NSCOUNT** | число авторитетных записей |
| 10–11 | **ARCOUNT** | число дополнительных записей |

2-байтовые числа записаны **big-endian** (сначала старший байт): `00 02` = 2.

### Флаги (16 бит)

| Бит(ы) | Поле | Значение |
|---|---|---|
| 15 | **QR** | 0 = запрос, 1 = ответ |
| 14–11 | **OPCODE** | 0 = обычный запрос |
| 10 | **AA** | авторитетный ответ |
| 9 | **TC** | ответ обрезан (*truncated*) |
| 8 | **RD** | прошу рекурсию (*recursion desired*) |
| 7 | **RA** | сервер умеет рекурсию (*recursion available*) |
| 6–4 | **Z** | зарезервировано (0) |
| 3–0 | **RCODE** | 0 = OK, 3 = **NXDOMAIN** (такого имени нет) |

:::example Разбор флагов по шагам [[own]]
У запроса флаги `0x0100`, у ответа `0x8180`.

1. `0x0100` = `0000 0001 0000 0000` → только бит 8 = 1 → **RD = 1** («ищи за меня до конца»).
2. `0x8180` = `1000 0001 1000 0000` → бит 15 (**QR = 1**, это ответ), бит 8 (**RD = 1**, скопирован из вопроса), бит 7 (**RA = 1**, сервер умеет рекурсию), RCODE = 0 (OK).
3. В Java: `int qr = flags >> 15 & 1; int rcode = flags & 0xF;`
:::

### Вопрос (question)

- **QNAME** — имя как цепочка меток: байт длины + буквы, в конце байт `00`.
- **QTYPE** — 2 байта, например `00 01` = A.
- **QCLASS** — 2 байта, `00 01` = IN (Internet).

`www.example.com` → `03 77 77 77 07 65 78 61 6D 70 6C 65 03 63 6F 6D 00` (3 буквы `www`, 7 букв `example`, 3 буквы `com`, конец).

### Запись ответа (resource record)

| Поле | Размер | Заметки |
|---|---|---|
| NAME | переменный | часто **указатель** `C0 0C` |
| TYPE | 2 B | например, 1 = A |
| CLASS | 2 B | 1 = IN |
| TTL | **4 B** | сколько секунд можно держать в кэше |
| RDLENGTH | 2 B | длина данных |
| RDATA | RDLENGTH | например, 4 байта адреса IPv4 |

:::note Сжатие имён (указатель)
Если байт длины начинается с битов `11` (то есть `>= 0xC0`), это **не** метка, а **указатель**: два байта, 14 бит которых — смещение в сообщении. `C0 0C` → смещение `0x0C` = 12 — там начинается имя из вопроса (сразу после 12-байтового заголовка). Так имя не повторяется в каждом ответе.

Смещение считается так: `((b1 & 0x3F) << 8) | (b2 & 0xFF)`.
:::

## Пример байт за байтом (настоящие данные из проверки этой страницы)

Запрос `example.com`, тип A (29 байт):

```text
70 C5 01 00 00 01 00 00 00 00 00 00 07 65 78 61
6D 70 6C 65 03 63 6F 6D 00 00 01 00 01
```

| Байты | Значение | Смысл |
|---|---|---|
| `70 C5` | ID = 0x70C5 | случайный номер запроса |
| `01 00` | флаги 0x0100 | RD = 1 |
| `00 01` | QDCOUNT = 1 | один вопрос |
| `00 00` ×3 | 0, 0, 0 | ответов и доп. записей нет |
| `07 65 78 61 6D 70 6C 65` | 7 + «example» | первая метка |
| `03 63 6F 6D` | 3 + «com» | вторая метка |
| `00` | — | конец имени |
| `00 01` | QTYPE = 1 | A |
| `00 01` | QCLASS = 1 | IN |

Ответ от `8.8.8.8` (61 байт):

```text
70 C5 81 80 00 01 00 02 00 00 00 00 07 65 78 61
6D 70 6C 65 03 63 6F 6D 00 00 01 00 01 C0 0C 00
01 00 01 00 00 01 2C 00 04 AC 42 93 F3 C0 0C 00
01 00 01 00 00 01 2C 00 04 68 14 17 9A
```

| Байты | Смысл |
|---|---|
| `70 C5` | тот же ID — это ответ на **наш** вопрос |
| `81 80` | QR = 1, RD = 1, RA = 1, RCODE = 0 |
| `00 01 00 02 00 00 00 00` | 1 вопрос, **2 ответа** |
| `07 65 … 00 00 01 00 01` | повторённый вопрос |
| `C0 0C` | NAME = указатель на смещение 12 → `example.com` |
| `00 01 00 01` | TYPE = A, CLASS = IN |
| `00 00 01 2C` | TTL = 0x12C = **300 с** |
| `00 04` | RDLENGTH = 4 |
| `AC 42 93 F3` | 172.66.147.243 (0xAC = 172, 0x42 = 66, 0x93 = 147, 0xF3 = 243) |
| `C0 0C … 68 14 17 9A` | второй ответ: 104.20.23.154 |

## Программа DnsLookup

@code(c6/DnsLookup.java)

Главное:

- `DataOutputStream.writeShort` пишет 2 байта в порядке **big-endian** — ровно как требует DNS.
- `u16` / `u32` читают числа без знака: `(m[i] & 0xFF) << 8 | (m[i+1] & 0xFF)`.
- `readName` понимает метки **и** указатели; после указателя имя заканчивается, поэтому позиция сдвигается только на 2 байта.
- Буфер 512 байт — классический лимит DNS по UDP (у больших ответов выставлен TC = 1).

:::danger `byte` в Java со знаком [[own]]
Байт `0xF3` в Java — это **−13**, а не 243. Без `& 0xFF` IP-адрес напечатается как `-84.66.-109.-13`. Всегда: `int value = b & 0xFF;`.
:::

### Запуск

```bash
javac DnsLookup.java
java DnsLookup example.com
java DnsLookup pjwstk.edu.pl MX
java DnsLookup www.wikipedia.org A 1.1.1.1
```

Фрагменты настоящих результатов:

```text
Answer: pjwstk.edu.pl  type=MX  TTL=3600 s  data=pref 1 ASPMX.L.GOOGLE.COM
Answer: www.wikipedia.org  type=CNAME  TTL=20707 s  data=dyna.wikimedia.org
Answer: dyna.wikimedia.org  type=A  TTL=180 s  data=208.80.153.224
Flags: 0x8183  QR=1 OPCODE=0 AA=0 TC=0 RD=1 RA=1 RCODE=3
RCODE 3 = NXDOMAIN (no such name)
```

Обрати внимание на **CNAME**: `www.wikipedia.org` — псевдоним, и сервер сразу добавил запись A для настоящего имени.

## DNS в nslookup и Wireshark

### nslookup — основы (из лабораторной)

```bash
nslookup www.example.com            # запись A (по умолчанию)
nslookup -type=NS example.com       # авторитетные серверы домена
nslookup -type=MX pjwstk.edu.pl     # почтовые серверы
nslookup 8.8.8.8                    # обратный запрос: IP -> имя
nslookup www.example.com 1.1.1.1    # спросить конкретный DNS-сервер
```

- Первые строки вывода — **DNS-сервер, который ответил** (имя и IP).
- **«Non-authoritative answer»** = ответ из **кэша** какого-то сервера, а не от авторитетного.

### Кэш DNS на твоём компьютере (из лабораторной)

Компьютер помнит недавние ответы. Чтобы увидеть запросы в Wireshark, сначала очисти кэш:

| Система | Команда |
|---|---|
| Windows | `ipconfig /flushdns` |
| macOS | `sudo killall -HUP mDNSResponder` |
| Linux (systemd) | `sudo resolvectl flush-caches` |

### Вопросы по перехвату

Очисти кэш DNS и браузера, запусти Wireshark с фильтром `dns` (или `ip.addr == <твой IP>`), открой любую страницу через `http://`, а потом сделай несколько `nslookup`.

::::task Вопросы D1–D8
1. DNS-запрос идёт по UDP или TCP?
2. Какой **порт назначения** у запроса и **порт источника** у ответа?
3. На какой IP-адрес отправлен запрос? Это твой локальный DNS-сервер по умолчанию?
4. Сколько вопросов и ответов в **запросе**? А в **ответе**?
5. Какого **типа** запрос отправляет `nslookup www...`? А `nslookup -type=NS ...`?
6. Что содержат ответы типа NS? Есть ли дополнительные записи (*additional*) и что в них?
7. Страница ссылается на картинку с **того же** сервера. Виден ли новый DNS-запрос перед вторым GET? Почему?
8. Найди пару запрос–ответ по **ID**. Совпадают?

:::answer Образцовые ответы (конкретные числа зависят от перехвата)
1. UDP.
2. Порт назначения запроса **53**; порт источника ответа **53** (порт клиента случайный).
3. Адрес локального DNS-сервера — сравни с `ipconfig /all` (Windows) или `resolvectl status` / `/etc/resolv.conf` (Linux).
4. Запрос: 1 вопрос, 0 ответов. Ответ: 1 вопрос (повторён) и ≥ 1 ответа.
5. `nslookup www...` → тип **A** (часто ещё отдельно **AAAA**). `-type=NS` → тип **NS**.
6. Имена авторитетных серверов; в секции *additional* часто их **IP-адреса** (записи A/AAAA) — «бесплатно», хотя мы их не просили.
7. Нет — адрес уже в **кэше DNS** компьютера, поэтому второй GET уходит сразу.
8. Да — у ответа всегда тот же ID, что у запроса; по нему клиент их сопоставляет.
:::

::::task 1. Другой DNS-сервер
Спроси одно и то же имя у `8.8.8.8`, `1.1.1.1` и у своего локального сервера. Сравни TTL. Почему они могут отличаться?

:::answer
TTL в ответе из кэша — это **оставшееся** время жизни записи: каждый сервер запомнил запись в свой момент, поэтому «отсчитывает» от разной точки.

:::cheatsheet
### Заголовок (12 B)
ID(2) · FLAGS(2) · QDCOUNT(2) · ANCOUNT(2) · NSCOUNT(2) · ARCOUNT(2) — big-endian.

### Флаги
QR(15) · OPCODE(14–11) · AA(10) · TC(9) · RD(8) · RA(7) · Z(6–4) · RCODE(3–0).
- запрос: `0x0100` (RD=1); типичный ответ: `0x8180`; NXDOMAIN: RCODE = 3.

### Сборка запроса по шагам
1. `writeShort(id)`, `writeShort(0x0100)`, `writeShort(1)`, 3× `writeShort(0)`.
2. Для каждой метки: `writeByte(длина)` + байты букв; в конце `writeByte(0)`.
3. `writeShort(QTYPE)` (A=1, NS=2, CNAME=5, MX=15, AAAA=28), `writeShort(1)` (IN).
4. Отправить по UDP на **порт 53**, буфер ответа 512 B, таймаут.

### Разбор ответа по шагам
1. Проверь **ID**, потом флаги и RCODE.
2. Прочитай счётчики.
3. Пропусти вопрос: имя + 4 байта.
4. Для каждой записи: NAME (осторожно с `C0 xx`), TYPE, CLASS, **TTL (4 B)**, RDLENGTH, RDATA.
5. A → 4 байта `& 0xFF` через точки.

### Ловушки
- `byte` со знаком → `& 0xFF`.
- Указатель: `b >= 0xC0`, смещение = `((b1 & 0x3F) << 8) | b2`; после указателя имя кончается.

### nslookup / Wireshark
- `nslookup имя`, `-type=NS`, `-type=MX`, `nslookup IP` (обратный).
- «Non-authoritative» = из кэша.
- Фильтр `dns`, `udp.port == 53`; очистка: `ipconfig /flushdns`.
:::
