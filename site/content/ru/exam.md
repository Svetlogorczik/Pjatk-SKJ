## Коротко

- На коллоквиуме пишешь **TCP-клиента**, который подключается к **серверу преподавателя**, логинится и решает задачи, приходящие **строками текста**.
- Каждую задачу нужно выполнить **несколько раз подряд** (в наборе 2025/26 — **5 раз**), и сервер сразу оценивает ответ.
- Типы задач: одна строка с числами → один ответ; несколько строк → один ответ; много строк → несколько ответов; **поток** (отвечаешь сразу, чтобы получить следующее число); поток **без заданной длины**.
- У теста **жёсткий срок** (время окончания указано в описании от сервера).
- Ниже — наш **тренировочный сервер** с теми же навыками, но другими действиями: можно тренироваться дома.

:::origin
В репозитории есть шаблон теста с прошлого года: клиент подключается к серверу на занятиях, отправляет свой идентификатор, получает **пароль** и **описание задач**, потом логинится паролем и решает 5 задач, каждую 5 раз. В оригинале задачи были про **склейку** (конкатенацию) чисел: из одной строки, из нескольких строк, парами, «первая половина со второй» при известном и неизвестном K. В описании «строка» определялась как байты ASCII, заканчивающиеся LF, CR или CRLF. У нашей тренировки **те же типы задач, но другие действия** (сумма, обратный порядок, суммы пар `BigInteger`, максимум пар).
:::

## Что проверяет коллоквиум (навыки)

| Навык | Где ты его тренировал |
|---|---|
| TCP-соединение, `readLine`, `flush` | [C3](c3-tcp-server.html), [C4](c4-text-protocol.html) |
| прочитать значение из ответа (например, пароль) и использовать дальше | шаг «вход» ниже |
| разбор чисел из строки (`split`, `parseLong`) | T1 |
| чтение известного числа строк | T2, T3 |
| числа **больше `long`** (`BigInteger` или операции над текстом) | T3–T5 |
| отправка **нескольких строк** ответа | T3 |
| ответ **сразу** во время потока | T4 |
| определение конца «пачки» по **тишине** (`setSoTimeout`) | T5 |

:::note Определение «строки» (из описания теста)
Строка — это последовательность байт ASCII, заканчивающаяся **LF** (`\n`), **CR** (`\r`) или **CRLF** (`\r\n`). Хорошая новость: `BufferedReader.readLine()` понимает **все три** окончания и возвращает строку без них. При отправке держись одного — `\r\n` самый надёжный.
:::

## Протокол тренировочного сервера DrillServer

| Шаг | Кто | Строка |
|---|---|---|
| 1 | клиент | `LOGIN <ник>` |
| 2 | сервер | `TOKEN <6 символов>` |
| 3 | клиент | `START <тот же токен>` |
| 4 | сервер | данные задачи T1, раунд 1 … |
| после каждого ответа | сервер | `OK` или `WRONG expected=<правильный ответ>` |
| в конце | сервер | `FINISHED <баллы>/<максимум>` и закрывает соединение |
| клиент молчит > 20 с | сервер | `TIMEOUT` и закрывает |

### Задачи (каждая повторяется R раз, по умолчанию 3)

| Задача | Сервер шлёт | Ты отправляешь | Пример |
|---|---|---|---|
| **T1** | 1 строку: `a b c` | 1 строку: **a + b + c** | `5 -2 10` → `13` |
| **T2** | 4 строки, по одному числу | 1 строку: числа **с конца**, через запятую | `1`,`2`,`3`,`4` → `4,3,2,1` |
| **T3** | 6 строк с **большими** числами | 3 строки: суммы пар (1+2, 3+4, 5+6) | `1…6` → `3`,`7`,`11` |
| **T4** | строку `K`, потом K чисел $a_1…a_K$, потом $b_1$ | после каждого $b_i$ **сразу** строку $\max(a_i, b_i)$; только тогда придёт $b_{i+1}$ | K=2: `2`,`10`,`20`,`15` → `15`, потом `5` → `20` |
| **T5** | как T4, но **без строки K** | как T4 — K нужно определить самому | — |

После T1, T2, T3 сервер проверяет ответ сразу; в T4 и T5 — после последней пары.

## Как тренироваться по шагам

:::steps
1. Скомпилируй: `javac DrillServer.java DrillClient.java`.
2. Запусти сервер: `java DrillServer 7777 3` (порт 7777, каждая задача 3 раза).
3. Заполни `TODO` в `DrillClient` — **по одной задаче за раз**. Остальные временно пропускай, отправляя что угодно.
4. Запусти клиента: `java DrillClient localhost 7777 3` и смотри логи `->` / `<-` и консоль сервера (там `OK` / `WRONG expected=…`).
5. Когда всё даёт `OK`, поставь 5 повторений и засеки время.
6. Только в самом конце сравни с образцовым решением (ниже).
:::

Консоль сервера при правильном решении (настоящая распечатка из проверки):

```text
[drill] student /127.0.0.1:43174: T1 OK
[drill] student /127.0.0.1:43174: T2 OK
...
[drill] student /127.0.0.1:43174: T5 OK
[drill] student /127.0.0.1:43174: finished with 15/15
```

## Подсказки к каждой задаче

:::hint T1 — разбор одной строки
`for (String part : line.trim().split("\\s+")) sum += Long.parseLong(part);` — `split("\\s+")` справляется с несколькими пробелами, `trim()` — с началом и концом. Используй `long` — сумма трёх `int` может выйти за пределы `int`.
:::

:::hint T2 — известное число строк
Прочитай ровно 4 строки в список, потом собери ответ с конца. Не читай «до конца» — сервер не закроет соединение, он ждёт тебя.
:::

:::hint T3 — большие числа
Числа до 30 цифр — в `long` (максимум ~9,2·10¹⁸) не влезут. Используй `new BigInteger(line.trim())` и `.add(...)`. Отправь **3 отдельные строки**.
:::

:::hint T4 — отвечай сразу
Прочитай K, потом K чисел в список. Затем в цикле `i = 0..K-1`: прочитай $b_i$ и **сразу** отправь `a.get(i).max(b)` + `flush`. Если попробуешь сначала прочитать все $b$ — клиент зависнет, потому что сервер пришлёт $b_{i+1}$ только после твоего ответа.
:::

:::hint T5 — неизвестное K: поймай тишину [[own]]
Сервер отправляет **одной пачкой** $a_1…a_K$ и $b_1$, а потом **замолкает**, потому что ждёт ответа. Поставь `socket.setSoTimeout(500)` и читай в цикле, пока не вылетит `SocketTimeoutException` — к этому моменту ты прочитал $K + 1$ чисел, значит $K = \text{количество} - 1$, а последнее прочитанное — это $b_1$. После этого верни `setSoTimeout(0)`. Это моё решение загадки из текста теста («как догадаться, сколько чисел будет прислано?»).
:::

## Как подойти к настоящему коллоквиуму [[own]]

:::steps
1. **Подготовь дома шаблон**: подключение, `send` / `read` с логами, запись в файл, `BigInteger`, обработку таймаута. На тесте нет времени писать это с нуля.
2. **Первое подключение = сохрани описание задач в файл** (как в [C4](c4-text-protocol.html)) — читать его спокойно, а не в консоли.
3. Посмотри **время окончания** теста и оставь себе запас.
4. Делай задачи **по порядку** и после каждой проверяй ответ сервера. Неправильный ответ в одной задаче может сдвинуть чтение следующих строк.
5. Каждую задачу выполняй **столько раз, сколько требует условие** (цикл!).
6. Пиши код, совместимый с **Java 8** — методов вроде `List.getFirst()` (Java 21) может не быть на компьютере в лаборатории.
7. Если что-то «зависло» — почти всегда ты ждёшь строку, которую сервер не пришлёт (неверный счётчик, непрочитанный вердикт, нет `flush`).
:::

### Частые ошибки

| Ошибка | Симптом | Исправление |
|---|---|---|
| не прочитан вердикт `OK/WRONG` | со следующей задачи всё «сдвинуто на строку» | после каждого ответа читай 1 строку вердикта |
| `in.available()` вместо подсчёта строк | то работает, то нет | читай известное число строк или используй таймаут |
| `int` / `long` для больших чисел | `NumberFormatException` или неверные результаты | `BigInteger` |
| нет `flush()` | сервер ждёт, ты ждёшь → `TIMEOUT` | `flush()` после каждого ответа |
| пробелы в конце строки | `NumberFormatException` | `trim()` |
| забыл вернуть `setSoTimeout(0)` | `SocketTimeoutException` в следующих задачах | возвращай в `finally` |

:::cheatsheet
### Шаблон клиента (ядро)
- `Socket s = new Socket(host, port);`
- `in = new BufferedReader(new InputStreamReader(s.getInputStream(), UTF_8));`
- `out = new PrintWriter(new OutputStreamWriter(s.getOutputStream(), UTF_8));`
- `send(x)`: `out.print(x + "\r\n"); out.flush();` + лог
- `read()`: `readLine()`; `null` → исключение; лог

### Шаблоны задач
- **1 строка, много чисел** → `split("\\s+")` + `Long.parseLong`.
- **N строк** → `for (i < N) list.add(read())`.
- **большие числа** → `new BigInteger(s)`, `.add`, `.max`, `.compareTo`.
- **несколько строк ответа** → отдельный `send` на каждую.
- **поток** → прочитал 1, ответил 1, `flush`.
- **неизвестная длина** → `setSoTimeout(500)` + `catch (SocketTimeoutException)` → вернуть `setSoTimeout(0)`.

### Порядок на тесте
1. Сохрани описание в файл. 2. Проверь срок. 3. Задача за задачей, с циклом повторений. 4. После каждого ответа читай вердикт.

### Тренировка
`java DrillServer 7777 3` → `java DrillClient localhost 7777 3` → цель: `FINISHED 15/15`.
:::
