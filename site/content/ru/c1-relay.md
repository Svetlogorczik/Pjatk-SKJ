## Коротко

- На первых занятиях задача — **запустить несколько процессов одновременно** и увидеть, что они общаются через сеть, даже на одном компьютере.
- У каждого процесса **свой порт** (свои «двери»), и он знает, **на какой адрес и порт** слать данные дальше. Это записывается в **конфигурационный файл**.
- Сначала нужно **открыть дверь** (`ServerSocket`), только потом кто-то сможет постучать (`Socket`).
- Наша версия: три узла A → B → C → A образуют **кольцо** и передают друг другу «палочку» (*token*), как в эстафете.

:::origin
На ćwiczeniach 1 запускалась готовая программа из нескольких окошек, соединённых по TCP в цепочку; каждое окошко читало из файла `.prop` адреса и порты соседей. Ниже — **наша переделанная версия** той же идеи: консольная, со своим кодом, где видно каждый шаг.
:::

## Словарик для старта

| Понятие | Что значит | Пример |
|---|---|---|
| **процесс** | запущенная программа | `java RelayNode relay-a.properties` |
| **IP-адрес** | «адрес дома» компьютера | `127.0.0.1`, `192.168.1.15` |
| **localhost** | «этот же компьютер» — всегда `127.0.0.1` | `nextHost=localhost` |
| **порт** | номер «двери» программы на компьютере (0–65535) | `7001` |
| **сокет** (*socket*) | конец соединения: IP-адрес + порт | `127.0.0.1:7001` |
| **сервер** | процесс, который **ждёт** подключений (`ServerSocket`) | узел слушает 7002 |
| **клиент** | процесс, который **подключается** к серверу (`Socket`) | узел A подключается к B |

:::own Важно: один процесс может быть одновременно сервером и клиентом
В кольце **каждый** узел — сервер (ждёт палочку от предыдущего) **и** клиент (отправляет её следующему). В проекте так же: proxy — сервер для клиентов и клиент для серверов.
:::

## Как работает наша эстафета

```text
        +-------------------+
        v                   |
   [A :7001] --> [B :7002] --> [C :7003]
   starter
```

:::steps
1. Каждый узел открывает свой порт (`ServerSocket`) и ждёт.
2. Узел **A** (стартер) отправляет B строку `TOKEN 1 0 A` (раунд 1, 0 переходов, путь «A»).
3. Каждый узел, получив строку: увеличивает счётчик переходов, дописывает своё имя в путь и передаёт дальше.
4. Когда палочка возвращается к A, A печатает итог раунда и начинает следующий.
5. После последнего раунда A отправляет `STOP`, который обходит кольцо, — каждый узел завершает работу.
:::

**Протокол** (формат, порядок, действия — см. [W1](w1-internet.html)):

| Сообщение | Формат | Действие получателя |
|---|---|---|
| палочка | `TOKEN <раунд> <переходы> <путь>` | +1 переход, дописать своё имя, отправить дальше |
| конец | `STOP` | отправить `STOP` дальше и завершиться (стартер просто завершается) |

Каждое TCP-соединение переносит **ровно одну строку** и закрывается.

## Код узла

@code(c1/RelayNode.java)

Самые важные места:

- `new ServerSocket(listenPort)` — открываем дверь. Если порт занят, вылетит `BindException: Address already in use`.
- `server.accept()` — **ждём** (программа «стоит»), пока кто-нибудь не подключится.
- `in.readLine()` — читаем **целую строку**, заканчивающуюся `\n`.
- `new Socket(nextHost, nextPort)` — подключаемся к следующему узлу. Если там никто не слушает, вылетит `ConnectException: Connection refused` — поэтому у нас есть **повтор** каждые 0,5 с.
- `PrintWriter(..., true)` — `true` значит автоматический `flush()` после `println`. Без flush данные могут застрять в буфере!

:::own Обрати внимание на порт клиента
В логе `from 127.0.0.1:53318` порт **53318** — не наш. Это **эфемерный порт**: система выбирает его случайно для каждого нового соединения на стороне клиента. «Постоянный» порт есть только у стороны, которая **слушает**.
:::

## Типичные ошибки и что они значат [[own]]

| Сообщение | Причина | Что делать |
|---|---|---|
| `java.net.ConnectException: Connection refused` | по этому адресу:порту **никто не слушает** (узел не запущен или порт не тот) | сначала запускай «серверы»; проверь порт в файле |
| `java.net.BindException: Address already in use` | порт **занят** — например, ещё работает прошлый запуск | закрой старый процесс или смени порт |
| `java.net.UnknownHostException` | такого имени хоста нет (опечатка) | исправь `nextHost` |
| `NumberFormatException` | в файле неверный номер порта, пробел или буква | исправь файл `.properties` |
| окно «Брандмауэр Windows» | Windows спрашивает разрешение на сеть для Java | разреши (частная сеть) |
| программа «висит» без ошибки | ждёт в `accept()` или `readLine()` — другая сторона ничего не отправила | проверь порядок запуска и `flush()` |

Полезные команды — кто занял порт?

```bash
# Windows
netstat -ano | findstr 7001
# Linux
ss -ltnp | grep 7001
# macOS
lsof -i :7001
```

:::cheatsheet
### Понятия
- Порт = «дверь» процесса (0–65535). Сокет = IP + порт.
- `localhost` = `127.0.0.1` = этот компьютер.
- Сервер: `new ServerSocket(port)` → `accept()` (ждёт).
- Клиент: `new Socket(host, port)` → подключается.
- Порт клиента случайный (эфемерный).

### Порядок запуска
1. Сначала процессы, которые **слушают**.
2. Потом тот, кто **начинает** отправлять.
3. Или: повторяй подключение каждые несколько сотен мс.

### Конфигурация
- `Properties p = new Properties(); p.load(new FileInputStream(файл));`
- `p.getProperty("listenPort")` → `Integer.parseInt(...)`.
- Никогда не хардкодь IP и порты.

### Ошибки
- `Connection refused` → никто не слушает.
- `Address already in use` → порт занят.
- «Висит» → ждёт в `accept()`/`readLine()`; проверь `flush()`.
- Кто занял порт: `netstat -ano | findstr PORT` / `ss -ltnp` / `lsof -i :PORT`.
:::
