## Коротко

- Сети **сложные**, поэтому их делят на **уровни**. Каждый уровень даёт **услугу** уровню выше и **пользуется** услугами уровня ниже.
- У стека Интернета **5 уровней**: прикладной, транспортный, сетевой, канальный, физический.
- Единицы данных: **сообщение** → **сегмент** → **датаграмма/пакет** → **кадр** → **биты**.
- **Инкапсуляция**: каждый уровень добавляет **свой заголовок** к данным уровня выше ($M$ → $H_tM$ → $H_nH_tM$ → $H_lH_nH_tM$).
- Модель **ISO/OSI** — **7 уровней**: плюс **представления** и **сеансовый**, которых в Интернете нет (если нужно, это делает приложение).

## Проблема: в сети куча деталей

Сеть — это хосты, роутеры, каналы разных типов, приложения, протоколы, железо, софт… Вопрос с лекции: **есть ли надежда как-то это упорядочить** — хотя бы в нашем разговоре о сетях?

## Аналогия с лекции: авиаперелёт

Перелёт — цепочка шагов, в которой участвует много служб:

| Вылет | Служба (уровень) | Прилёт |
|---|---|---|
| билет (покупка) | служба билетов | билет (жалоба) |
| багаж (сдача) | служба багажа | багаж (получение) |
| выход (посадка) | служба выходов | выход (высадка) |
| взлёт с полосы | служба полосы | посадка на полосу |
| ведение самолёта | **прокладка маршрута** | ведение самолёта |

**Уровни**: каждый уровень реализует **услугу**

- с помощью **своих внутренних действий**,
- **опираясь на услуги** уровня ниже.

Пример: служба багажа не знает, как вести самолёт, — она просто отдаёт чемодан «вниз» и доверяет, что он долетит.

## Зачем уровни?

С лекции:

- **Явная структура** позволяет назвать части сложной системы и описать связи между ними — **многоуровневая модель** как общий язык.
- **Модульность** упрощает поддержку и обновление: изменение **реализации** услуги одного уровня **незаметно** для остальной системы. Например, смена процедуры на выходе к самолёту не влияет на остальную поездку.

Лекция задаёт и вопрос: *«уровни вредны?»*

:::own Когда уровни мешают?
- **Дублирование работы** — например, проверка ошибок сразу на нескольких уровнях.
- **Накладные расходы** — каждый заголовок это лишние байты (посчитаем ниже).
- Иногда уровню **нужна информация с другого уровня** (видеоприложение хотело бы знать загрузку сети), а строгое деление на уровни этому мешает.
:::

## Стек протоколов Интернета (5 уровней)

| № | Уровень | Задача | Примеры протоколов |
|---|---|---|---|
| 5 | **прикладной** (*application*) | поддержка сетевых приложений | IMAP, SMTP, HTTP |
| 4 | **транспортный** (*transport*) | передача данных **между процессами** | TCP, UDP |
| 3 | **сетевой** (*network*) | **маршрутизация датаграмм** от источника к цели | IP, протоколы маршрутизации |
| 2 | **канальный** (*link*) | передача данных между **соседними** элементами сети | Ethernet, 802.11 (WiFi), PPP |
| 1 | **физический** (*physical*) | биты «на проводе» | — |

### Как называются данные на каждом уровне?

| Уровень | Единица данных |
|---|---|
| прикладной | **сообщение** (*message*) |
| транспортный | **сегмент** |
| сетевой | **пакет / датаграмма** |
| канальный | **кадр** (*frame*) |
| физический | **биты** |

## Инкапсуляция

Когда отправитель шлёт сообщение $M$, данные идут **вниз** по стеку, и каждый уровень добавляет **свой заголовок**:

:::steps
1. Приложение создаёт **сообщение** $M$.
2. Транспортный уровень добавляет заголовок $H_t$ → **сегмент** $H_t M$.
3. Сетевой уровень добавляет $H_n$ → **датаграмма** $H_n H_t M$.
4. Канальный уровень добавляет $H_l$ → **кадр** $H_l H_n H_t M$.
5. Физический уровень отправляет **биты**.
:::

По дороге:

- **switch** (коммутатор) смотрит только на **канальный** уровень (и физический),
- **роутер** смотрит на **сетевой** уровень (и ниже): распаковывает кадр, читает IP-заголовок, упаковывает в новый кадр для следующего канала.

У получателя всё наоборот (**декапсуляция**): каждый уровень снимает **свой** заголовок и отдаёт остальное наверх, пока приложение не получит чистое $M$.

:::own Аналогия: письмо в конвертах
Ты пишешь письмо ($M$), кладёшь его в конверт с номером комнаты (транспорт), этот конверт — в больший с адресом здания (сеть), а тот — в мешок курьера с номером маршрута (канал). Каждый посредник открывает только «свой» конверт.
:::

:::example Сколько стоят заголовки? [[own]]
Типичные размеры: заголовок TCP 20 B, IP 20 B, Ethernet 18 B (14 B заголовка + 4 B контрольной суммы). Отправляем 100 B данных приложения.

1. Все заголовки: $20 + 20 + 18 = 58$ B.
2. Весь кадр: $100 + 58 = 158$ B.
3. «КПД»: $100 / 158 \approx 63\%$ — больше трети это чистые накладные расходы!
4. Для 1460 B данных: $1460 / 1518 \approx 96\%$. Вывод: маленькие пакеты тратят канал впустую.
:::

## Эталонная модель ISO/OSI (7 уровней)

| № | Уровень OSI | Есть в Интернете? |
|---|---|---|
| 7 | прикладной | да |
| 6 | **представления** (*presentation*) | **нет** |
| 5 | **сеансовый** (*session*) | **нет** |
| 4 | транспортный | да |
| 3 | сетевой | да |
| 2 | канальный | да |
| 1 | физический | да |

- **Представления**: позволяет приложениям **понимать смысл** данных — шифрование, сжатие, машинно-зависимые соглашения.
- **Сеансовый**: **синхронизация**, контрольные точки (*checkpointing*), **восстановление** обмена данными.

В стеке Интернета **этих двух уровней нет**. Если такие услуги нужны, их должно реализовать **приложение**. Лекция спрашивает: *а они нужны?*

:::own Пример с наших занятий
Кодировка символов (`StandardCharsets.UTF_8` в Java) или Base64 в HTTP — это как раз «представление», и делает его **твоё приложение**. Мнемоника для 7 уровней OSI (снизу вверх): **P**lease **D**o **N**ot **T**hrow **S**ausage **P**izza **A**way = Physical, Data link, Network, Transport, Session, Presentation, Application.
:::

## Wireshark и уровни

Слайд с лекции показывает, как работает **Wireshark**:

- **захват пакетов** (*packet capture*, pcap) получает **копию каждого кадра Ethernet**, отправленного и полученного компьютером,
- **анализатор пакетов** распаковывает его уровень за уровнем: канал (Ethernet) → сеть (IP) → транспорт (TCP/UDP) → приложение (браузер, почтовый клиент).

:::own Где это видно в Wireshark?
Средняя панель Wireshark показывает дерево ровно в порядке инкапсуляции:

```text
Frame 42: 589 bytes on wire            <- физический уровень (сколько байт прошло)
Ethernet II, Src: ..., Dst: ...        <- канальный уровень (Hl)
Internet Protocol Version 4, Src: ...  <- сетевой уровень (Hn)
Transmission Control Protocol, Src Port: 51234, Dst Port: 80  <- транспорт (Ht)
Hypertext Transfer Protocol            <- приложение (M)
```

Щелчок по строке подсвечивает соответствующие байты в нижней панели.
:::

## Проверь себя [[own]]

:::check Как называется единица данных на транспортном, сетевом и канальном уровне?
Сегмент, датаграмма (пакет), кадр.
:::

:::check На какой уровень смотрит switch, а на какой роутер?
Switch — на канальный (2). Роутер — на сетевой (3).
:::

:::check Каких уровней OSI нет в стеке Интернета и кто берёт на себя их задачи?
Представления и сеансового. Их задачи (шифрование, сжатие, синхронизацию) выполняет приложение.
:::

:::check Что значит «изменение реализации уровня прозрачно»?
Остальные уровни его не заметят — пока уровень даёт ту же услугу, его можно как угодно переделать (например, заменить кабель на WiFi без изменения браузера).
:::

:::cheatsheet
### 5 уровней Интернета (сверху вниз)
| # | Уровень | Единица | Протоколы |
|---|---|---|---|
| 5 | прикладной | сообщение | HTTP, SMTP, IMAP, DNS |
| 4 | транспортный | сегмент | TCP, UDP |
| 3 | сетевой | датаграмма/пакет | IP, маршрутизация |
| 2 | канальный | кадр | Ethernet, WiFi, PPP |
| 1 | физический | биты | — |

### Инкапсуляция
- $M$ → $H_tM$ → $H_nH_tM$ → $H_lH_nH_tM$ → биты.
- Switch: уровни 1–2. Роутер: уровни 1–3. Хост: 1–5.

### OSI = 7 уровней
- Интернет + **представления** (шифрование, сжатие) + **сеансовый** (синхронизация, контрольные точки).
- Мнемоника: Please Do Not Throw Sausage Pizza Away.

### Накладные расходы заголовков по шагам
1. Сложи заголовки (например, TCP 20 + IP 20 + Ethernet 18 = 58 B).
2. Кадр = данные + заголовки.
3. КПД = данные / кадр.
:::
